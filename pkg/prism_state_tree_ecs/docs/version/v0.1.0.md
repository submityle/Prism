# prism_state_tree_ecs v0.1.0

## ST1 最小装配切片

已交付：

- `StateTreeAsset` 以 `Arc<Plan>` 共享不可变编译计划；每个 `StateTreeInstance` 持有长期存活的 core `Instance` 和独立运行时状态。core `Guard` 约束为 `Send + Sync`，因此该实例可作为 ECS Component。
- `queue_spawn` 使用 `prism_ecs::CommandQueue` 延迟创建带实例组件的实体。
- `request_event` 只向 core 有界 FIFO 入队；`step` / `tick_entity` 在调用者选定的独占世界 tick 边界执行初始化、消费事件和迁移。
- `set_guard` 将 thread-safe 的纯 guard 安装到对应实体自己的持久 runtime；guard 求值可真实允许或拒绝迁移，不修改共享 `Plan`。
- 集成测试覆盖 CommandQueue spawn、首次 tick 初始状态、请求事件后保持原配置、下一 tick 切换状态、资产句柄共享、事件队列满、预算错误和失效实体 no-op（15 tests）。
- crate 保持 `no_std + alloc`，无额外 feature。

已交付：core `Schema`/`ContextRef` 的显式 ECS adapter 边界：`ValidatedContext` 校验借用上下文的稳定 schema 身份，并由 `validate_context` 提供无隐式 World gather 的检查入口。该切片不持有 ECS World、不执行 gather，也不提供 typed binding。

已交付：`tick_entities` 按调用者给定顺序显式逐实体执行，保留重复实体，返回逐条结构化结果和统计；缺失条目区分 stale entity、尚未 materialize 的 reservation，以及已 materialize 但缺少 `StateTreeInstance` 组件三种原因，均为安全 no-op，单个 runtime 错误不会阻断后续请求。`tick_all` 通过真实 `World::query_filtered::<Entity, With<StateTreeInstance>>` gather 所有实例，按 generational Entity 排序后复用同一执行路径；内存预留失败以结构化错误返回。失败条目同时记录错误后的 active configuration 和剩余事件数，因为 core tick 失败不提供事务回滚。两者都由调用者显式触发，不注册 Schedule、不做 observer 调度。`prism_ecs` 依赖显式关闭默认 `std` feature，保证 no-std 构建不会由依赖默认 feature 引入标准库。

尚未交付（仍为 PLANNED）：自动 Schedule 系统注册、typed binding、迁移 observer 事件桥接、资产加载/热重载、回滚快照的 ECS 接线、Task/Evaluator、Debugger 和基准。当前 tick 仍是调用者显式驱动的 API，不提供“零配置插件”或全自动调度承诺。生命周期 callback 在 ST1 adapter 中使用 `NoopLifecycle`，因此 ECS observer 迁移通知也未接通；guard 安装 API 尚未在 adapter 上转发。
