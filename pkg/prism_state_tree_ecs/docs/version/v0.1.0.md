# prism_state_tree_ecs v0.1.0

## ST1 最小装配切片

已交付：

- `StateTreeAsset` 以 `Arc<Plan>` 共享不可变编译计划；每个 `StateTreeInstance` 持有长期存活的 core `Instance` 和独立运行时状态。core `Guard` 约束为 `Send + Sync`，因此该实例可作为 ECS Component。
- `queue_spawn` 使用 `prism_ecs::CommandQueue` 延迟创建带实例组件的实体。
- `request_event` 只向 core 有界 FIFO 入队；`step` / `tick_entity` 在调用者选定的独占世界 tick 边界执行初始化、消费事件和迁移。
- `set_guard` 将 thread-safe 的纯 guard 安装到对应实体自己的持久 runtime；guard 求值可真实允许或拒绝迁移，不修改共享 `Plan`。
- 集成测试覆盖 CommandQueue spawn、首次 tick 初始状态、请求事件后保持原配置、下一 tick 切换状态、资产句柄共享、事件队列满、预算错误和失效实体 no-op，以及确定性 gather、Schedule 报告/事件发布和 typed context gather（默认 feature 21 tests；启用 `app` feature 时为 22 tests，另含 1 个 plugin 回归测试）。
- crate 保持 `no_std + alloc`，无额外 feature。

已交付：core `Schema`/`ContextRef` 的显式 ECS adapter 边界：`ValidatedContext` 校验借用上下文的稳定 schema 身份，并由 `validate_context` 提供无隐式 World gather 的检查入口。该切片不持有 ECS World、不执行 gather，也不提供 typed binding。

已交付：`tick_entities` 按调用者给定顺序显式逐实体执行，保留重复实体，返回逐条结构化结果和统计；缺失条目区分 stale entity、尚未 materialize 的 reservation，以及已 materialize 但缺少 `StateTreeInstance` 组件三种原因，均为安全 no-op，单个 runtime 错误不会阻断后续请求。`tick_all` 通过真实 `World::query_filtered::<Entity, With<StateTreeInstance>>` gather 所有实例，按 generational Entity 排序后复用同一执行路径；adapter 自己的 gather 缓冲区预留失败以结构化错误返回，ECS query cache、report 和 runtime 内部的其他分配仍遵循各自 API 的宿主分配语义。失败条目同时记录错误后的 active configuration 和剩余事件数，因为 core tick 失败不提供事务回滚。另提供 `install_tick_system` 将 rotation 双缓冲事件和确定性 gather/tick 路径注册到宿主 `Schedule`，事件保留标准两次 update grace window，每次 schedule run 执行一次，并以 `StateTreeTickReport` 资源保留 `BatchTickReport` 或 gather 失败。`StateTreeInstance` 以 `StateTreeLifecycleEvent` 队列保留 core 的 enter/exit/transition 顺序；Schedule 接线会把这些事件包装为带 `Entity` 的 `StateTreeLifecycleNotification`，写入标准 `Events<StateTreeLifecycleNotification>` 双缓冲资源。`EcsSchema`/`gather_context` 提供显式 typed ECS context gather、借用 `World` 和 owner/context 缺失错误。显式 `tick_entities`/`tick_all` 仍可由调用者直接消费实例队列；这不是无载荷 marker observer。`prism_ecs` 依赖显式关闭默认 `std` feature，保证 no-std 构建不会由依赖默认 feature 引入标准库。

已交付：启用 `app` feature 时，`StateTreePlugin` 将 rotation/tick 系统注册到 `prism_app::Update`；该入口保持显式 opt-in，不提供 zero-config 插件或自动资产/Context 装配。

2026-10-14 的 `reflect` 增量：已编译路径的 typed get/set 可直接使用；`encode_typed` / `decode_typed` 通过 core `SlotCodec` 在反射标量与实例帧之间双向转换，目前支持 bool、u32/i32、u64/i64、f32/f64，错误时保留原帧字节。

2026-10-14 的 `authoring` 增量：`serialize_tree_def` / `parse_tree_def` 提供版本化 canonical text，覆盖全部当前 `TreeDef` 字段；解析阶段执行 core 结构校验，拒绝未知字段、乱序字段、空行、尾随输入和非法定义。

2026-10-14 的 `snapshot_bridge` 增量：`StateTreeInstance` 和 ECS `World` 均可捕获/恢复 core 的 v2 二进制快照；解码先于可变组件借用，core 计划指纹、队列容量与结构校验通过后才替换实例状态。stale、未 materialize、缺少组件、编码、解码和恢复错误均有结构化类型；34 项 all-features 单测和 0 文档测试通过，严格 Clippy 通过。当前 Schedule 入口保持显式 `install_tick_system`，生命周期通知通过 `Events<StateTreeLifecycleNotification>` 发布，不改变确定性 tick 路径。
