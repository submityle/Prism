# Loom 与 Bevy BSN 对比

> 本文先概述 Bevy BSN 的现状与定位,再逐维度给出评析,最后说明 Loom 在每一点上的改进。
> 评析立足于公开可见的 BSN 设计方向,结论服务于 Loom 的取舍,不代表对 BSN 的最终评价。

## 1. 什么是 BSN

BSN(Bevy Scene Notation)是 Bevy 新一代的 **声明式场景 / UI 记法**,用一套宏语法
把「结构(spawn 哪些实体)+ 构造(挂哪些组件)+ 数据(组件初值)」统一表达,并配套
`.bsn` 资产格式,目标是取代样板繁多的命令式 `spawn` 与难手写的 `.scn.ron`。

**优点**:

- **ECS 原生**:直接映射到 Entity + Component,与 Bevy 的世界模型天然一致。
- **类型安全的宏**:结构在编译期检查,组件 / 字段写错即编译报错。
- **一处声明**:把实体层级与初始组件集中写在一起,比命令式 `spawn` 链更紧凑。

## 2. 逐维度评析与 Loom 的改进

| 维度 | BSN | Loom 的做法 |
|---|---|---|
| 关注点分离 | 结构 + 构造 + 数据耦合在同一套语法里,演进较慢 | **结构 / 响应 / 样式三层分离**,各自独立编写、测试、演进 |
| 更新粒度 | 偏场景级 / 实体级 patch | **字段级增量**:协调器只发出 `SetText`/`SetPaint`/`Reorder` 等真实差异 |
| archetype 搬迁 | 运行期改变组件集合时可能触发 | **显式规避**:更新只改组件「值」,频繁切换态用枚举字段 |
| 独立样式层 | 无独立样式层,样式与结构混写 | **独立 token + class + 级联**,设计与结构解耦,规划中支持热重载 |
| 动画 / 效果 | 非一等公民,需外接动画系统 | **一等公民**:缓动 / 弹簧 / 时间线 / 过渡内置于 `prism_ui_anim` |
| 组件 / 状态 / 路由 / i18n | 无独立层,靠宏片段拼接 | **一等独立 crate**:`prism_ui_component` / `store` / `router` / `i18n` **均已交付** |
| 异步 / 错误边界 | 较弱 | 规划 **Suspense + Error Boundary**(roadmap M5) |
| 类型安全 | 强(宏) | **强(宏)**,`loom!` 展开为全限定构建器调用,错误即编译报错 |
| 热重载 | 规划中 / 逐步成熟 | 规划 **结构 + 样式热重载且保留运行时状态**(roadmap) |

## 3. 关键差异详解

### 3.1 关注点分离

BSN 把结构、构造与数据初值绑在一套语法里。好处是「一处看全」,代价是三件事的演进
被耦合:想单独迭代样式系统或响应模型,都要动同一套宏。

Loom 把它们拆成三层独立 crate:
- 结构层 `loom!` / `Element` 只描述「长什么样、有哪些子节点」;
- 响应层 `prism_ui_reactive` 独立提供 Signal/Memo/Effect;
- 样式层 `prism_ui_style` 独立提供 token/class/级联。

三层可各自单测、各自演进。这是「易维护」的根本结构差异。

### 3.2 更新粒度与 archetype 搬迁

ECS 的一个性能陷阱是:运行期增删组件会改变实体的 archetype,触发内存搬迁。
若声明式层在状态变化时「插入/移除标记组件」,就可能在热路径上反复搬迁。

Loom 的协调器产出的更新本质是 **字段级** 的(改 text、改 paint、改顺序),对应到
ECS 时策略是「改组件值,不插删组件」。可切换态(显示/隐藏、选中/未选中)用
**枚举或标志字段** 表达,而非增删 marker 组件,从源头规避搬迁。

### 3.3 动画作为一等公民

在 BSN 里动画通常由外部系统驱动,记法本身不表达过渡。Loom 把动画内建:
`prism_ui_anim` 提供缓动曲线(含用 Newton/二分求解的 CubicBezier)、解析式阻尼弹簧、
关键帧时间线、进出场 `Transition`。样式层未来还会支持 `transition:` 声明实现
「属性变化即自动补间」的隐式过渡(roadmap M4)。

### 3.4 可验证的性能契约

BSN 的性能取决于使用者是否踩中 archetype 搬迁等陷阱,较难直接度量。Loom 用
`RecordingBackend` 把「本次更新产生了哪些操作」变成可断言的事实:相同输入零新增、
keyed 反转 0 新建 0 删除 1 reorder 等,都是现有测试里被钉死的回归用例。

## 4. 诚实的边界

- Loom 当前 **已交付** 的是数据层 `Element` → 保留树 → `BackendOp` 的完整链路,
  以及独立可用的响应 / 样式 / 布局 / 动画四层与 `loom!` 宏。
- **已交付的高级层**:组件模型(`prism_ui_component`)、全局状态(`prism_ui_store`)、
  国际化(`prism_ui_i18n`)、路由(`prism_ui_router`)、DevTools 基线(`prism_ui_devtools`),
  详见 [advanced-features.md](advanced-features.md)。它们目前是 **引擎弱耦合** 的独立运行时能力。
- 仍为 **规划中**:「响应式信号自动绑定到 ECS 实体字段」「`.loom` / `.loom.style` 资产热重载」
  「Suspense / Error Boundary / Portal / 列表虚拟化 / 共享元素过渡」等,见
  [roadmap.md](roadmap.md)。本对比不把这些未实现能力计入「已胜出」。
- BSN 作为 Bevy 官方方案,在 **与 Bevy 生态的原生集成度** 上天然领先;Loom 的取舍
  是 **引擎弱耦合 + 可测试的最小增量更新**,两者定位不同。
