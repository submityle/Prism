# prism_state_tree_core v0.1.0

## ST0 语义内核

这是 StateTree 的首个可用核心切片：`TreeDef` 经结构校验编译为不可变 `Plan`，运行时以有界事件队列驱动确定性微步。

已交付：

- Atomic、Compound、Parallel 状态与稳定的活跃配置；
- Event / Eventless 迁移、priority + 声明顺序裁决、祖先迁移继承；
- LCA 生命周期、Internal / External / Self 迁移区别；
- Shallow / Deep history；
- guard、FIFO 事件队列、微步预算、生命周期与迁移日志；
- 可校验的 no_std 快照编码/解码与原子恢复；微步预算阻断时未执行事件保留在 FIFO 队首；
- Transition 语义覆盖严格后代、祖先重入与跨 Parallel region 的配置退出，定义编译拒绝重复 child/region 及非法 history owner；
- Parallel Deep History 重入不会叠加默认 region 子状态；Parallel owner 转移后会补齐所有 region；History 请求深度必须与 owner 配置一致，否则编译期拒绝；预算错误仍保留已执行状态变化，但不返回部分 `StepReport`；
- `no_std + alloc`、`forbid(unsafe_code)`，不依赖 ECS、渲染、网络或编辑器。
- 诊断日志默认关闭；启用时由调用方设置固定容量，满后保留已有记录、置位溢出标志并让 `start`/`run` 返回 `LogCapacityExceeded`，但生命周期回调和状态变更不被截断；`clear_log` 可复位该状态。

## ST2 数据层核心契约

本版本新增了不依赖宿主存储的 binding 编译基础，作为 `prism_reflect` / ECS adapter 的稳定接入边界：

- `BindingPath` 严格解析 dotted identifier，并拒绝空段、非法字符和含糊路径；
- `BindingSlot(u32)` 表示实例帧中的稳定槽位索引；
- `EvaluatorDependency` 声明 evaluator 到输入 slot 的依赖；
- `DependencyPlan` 编译确定性反向索引，输入 slot 变化时只返回受影响的 evaluator，结果按 evaluator id 排序并去重；
- 重复 evaluator id 与同一 evaluator 的重复输入 slot 在编译期拒绝。
- 反向索引按实际使用的 slot 稀疏存储，可处理 `u32::MAX` slot；`dirty_evaluators_into` 复用调用方容量，不分配，容量不足返回 `OutputCapacity` 并清空结果。

core 保持 `prism_reflect`、ECS `World` 和字符串热路径读取在宿主 adapter 之外；Schema 诊断与静默实例基准分别由本 crate 的结构化 API 和 benchmark 提供证据。

2026-10-14 的 ST2 增量：`FrameLayout`/`InstanceFrame` 增加对齐布局和范围检查；`SlotCodec` 编译固定宽度 typed slot 并校验稳定 GUID、版本和默认值，热路径按 little-endian 定长读写。`FrameSnapshot` 规范化 padding，以布局/Schema 指纹及校验哈希拒绝不兼容或篡改数据，失败不更改目标帧。`FrameMigration` 按 GUID 复制兼容字段、给新增字段填充默认值；同 GUID 的类型或版本变化明确拒绝。单槽读写和预留缓存的依赖索引读取无分配，整树静默路径的分配证据由 `benches/runtime_scale.rs` 给出。

## Schema / Context 基础契约

已交付：

- 稳定的 `SchemaId`、`SchemaVersion`、`SchemaDescriptor` 与结构化 `SchemaError`。
- `SchemaCapabilities` 能力位的组合、查询与未知位拒绝。
- 只读、借用宿主上下文的 `ContextRef`，以及 `Schema::validate_context` 的 schema 身份校验。
- 该切片保持 core 的 `no_std + alloc` 边界；不引入 ECS `World`/`Entity`，不伪造 gather、typed binding 或自动调度。

2026-10-14 运行时增量：启动时预留活跃配置与进入路径容量；过渡不再克隆 `Transition`，退出、并行 region 修复与历史恢复不再建立临时状态数组；重复捕获历史复用对应 owner 的缓存；诊断日志改为显式定容并报告溢出。运行时语义回归、并行深历史缓存复用、日志容量与回调独立性均有测试覆盖；整树静默路径由 benchmark 统计分配/释放计数。

2026-10-15 ST3/ST5/ST8 增量：`validator.rs` 提供有界静态诊断（ST0001、ST0006、ST0007、ST0099），`model_verify.rs` 增加 reachability、transition coverage、deadlock candidate、eventless cascade 和有限路径枚举；`snapshot.rs` 将快照格式升级为 v2 计划语义指纹并保留 v1 读取兼容；`replay.rs`、`counterfactual.rs` 提供有界轨迹分叉与第一处分歧 diff；`revision.rs`、`behavior_pack.rs` 提供 PlanRevision 握手、稳定契约、SemVer、灰度和回滚。

## ST8 工程化合同

`task_contract.rs` 提供 `Outcome`、固定步 `Cadence`、规范化 `AccessSet`、`ReplaySafety`、`AbortReason`、可扩展 `InterruptTier`、四种开闭端点的 `CancelWindow` 与固定容量 `RequestQueue`。`telemetry.rs` 提供驻留、迁移、guard、LOD 和预算聚合；`resilience.rs` 提供 FrameBudget、Closed/Open/HalfOpen CircuitBreaker、每树 SafeMode 和固定容量事件缓冲；这些合同均保持 no_std、无 unsafe、确定性和有界内存。

本版本 core 测试为 107 项单测、0 文档测试；`cargo test -p prism_state_tree_core --offline` 与 `cargo clippy -p prism_state_tree_core --all-targets --offline -- -D warnings` 均于 2026-10-15 通过。

## 确定性回放与计划修订

本版本还提供两个可直接复用的确定性基础件：

- `TraceLog` 以固定容量记录 `Start` 和单事件 run-to-completion 输入，并保存计划语义摘要与 active-state digest；`replay` 在第一处摘要不一致时返回记录序号、输入、期望值和实际值。它不读取运行时私有字段，不改变运行语义，也不要求调试器或序列化框架。
- `PlanRevision` 与 `MigrationDecisionSet` 为热重载提供有界、可审计的修订握手：相同指纹为 `Exact`，不同指纹必须显式记录 `Preserve`、`Reinitialize` 或 `Remove` 决策并提交接受/拒绝 verdict。`MigrationKey` 保持不透明，宿主负责 StateGuid/SlotGuid 到实例数据的实际映射。

## 可复现性能基准

`benches/runtime_scale.rs` 是离线可运行的 plain benchmark，预热后测量静默实例的每帧 P50/P95/P99，并由全局计数分配器检查运行期分配与释放。2026-10-14 在 Apple M2、8 核 CPU、16 GB 内存、macOS 27.0.1 上，以 `STATE_TREE_BENCH_INSTANCES=100000 cargo bench -p prism_state_tree_core --bench runtime_scale --offline` 执行：100,000 实例、4 帧/样本，P50 `1,294,052 ns/frame`、P95 `1,316,958 ns/frame`、P99 `1,380,468 ns/frame`，分配 `0`、释放 `0`。该报告是静默两状态树的实测样本，不替代深层树、事件密集树或宿主 ECS gather 的独立报告。

core crate 的稳定职责包括语义内核、帧/槽位编解码、静态验证、模型验证、快照、回放、反事实调试、任务合同、遥测、韧性、行为包和计划修订契约；ECS gather、批处理、LOD、GPU batch contract、反射 scalar adapter 和资产作者化位于 `prism_state_tree_ecs`，真实设备 compute adapter 位于 `prism_state_tree_gpu`，各 crate 的版本记录给出对应验证命令。
