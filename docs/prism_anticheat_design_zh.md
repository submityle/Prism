# Prism Anticheat 顶级次世代 AAA 级权威式反作弊服务设计方案

> 面向 Prism（脱离 Bevy 后的独立引擎）的 **反作弊** 设计。核心立场有二，且本次重构把第二条提到与第一条同等的高度：
> 1. **权威式确定性策略**：安全强度来自「权威式确定性校验（提议约束 + 事件流重放对账）+ 速率限制与配额 + 会话完整性与重放防护 + 可解释统计阈值 + 分级处置（flag / throttle / kick / ban / 影子 / 遥测）+ 审计日志与举报回放」，**引擎基座与默认服务不含内核态 / 驱动级组件**（内核态仅作可选客户端加固档 Tier 2：opt-in、feature + 平台门控、信号一律软、安全根不下放，第一方实现 TODO 待设计，见 §25.3）、**不含任何 AI/ML**。
> 2. **反作弊是独立服务，不是引擎 crate**：反作弊**不随引擎发行、不放在引擎工作区 `pkg/` 下**，而是一套**独立仓库、独立版本、独立发布节奏的产品化服务**（self-hosted 库 / sidecar / 托管云三形态，**可能收费**）。引擎侧 `pkg/` 只保留**一个零成本接缝** `prism_net_acheat_api`（`AntiCheatProvider` trait + 钩子上下文 + 默认 no-op）；服务通过这个接缝插入网络权威回路，引擎不依赖服务、服务不进引擎工作区。
>
> **架构立场**：反作弊不另立安全根。安全强度的上限由 `prism_network` 提供的三条**不可替换根基**决定——服务器唯一权威、确定性可对账、传输会话完整性（network §14.1）。本服务只做**策略层**：在网络暴露的钩子点（network §14.2）上，以确定性、可解释、可裁剪的规则判定「客户端提议是否能在权威仿真中复现」，并给出处置与遥测。客户端侧检测一律视为**可被破解的噪声过滤**，不作安全根。
> **模块化与可替换**：从引擎视角看，整个反作弊服务只是接缝背后的一个 provider——可整体或局部替换为官方服务 / 第三方商用 / 自定义 / no-op（可信局域网与单机）；由 feature `anticheat` 门控，关闭即编译期移除、无运行时税。唯一不可替换的是它赖以生效的网络根基不变量——服务只能插进这套骨架、不能违反它（§16、§22、network §22）。
> **性能立场（本次重构重点）**：反作弊天然要「热路径快、重活异步」，而「独立服务」又引入「可能跨进程 / 跨机」的现实。为同时满足二者，本设计确立 **快路径 / 深路径分离架构**（§4）：同步硬拒绝只走**进程内守卫**（本地、`O(1)~O(log n)`、零堆分配、绝不网络往返），深度对账 / 计分 / 编排 / 跨局关联 / 封禁与申诉只走**异步服务侧**（消费权威事件流，可本地、可 sidecar、可托管云）。这条分界线既保手感又保安全，还让「可收费的重活」自然落到可独立计费的服务侧。
> 借形态不抄码。借鉴：
> - **权威式仿真校验**：Valve VAC / Source（服务器唯一权威、运动与命中回溯校验、信任客户端为零）、Overwatch（command frame 权威对账）、Rocket League（fixed-tick 确定性重放交叉验证）
> - **服务化 / 可插拔集成形态**：Easy Anti-Cheat / BattlEye 的「引擎暴露钩子、反作弊作独立产品接入」边界划分，与「客户端组件 + 服务端后台 + 托管运营」的产品形态（借其**边界划分与服务化形态**；其**客户端内核态加固**仅作**可选加固档**借鉴形态——默认不含、opt-in、信号一律软、安全根不下放，第一方实现 TODO 待设计，见 §24、§25.3）
> - **大规模遥测与计分**：Riot（可解释硬阈值 + 行为计数聚合，服务器侧裁决）、EVE（审计日志 append-only + 回放复盘）、MMO 经济守恒审计（资源进出账守恒校验）
> - **一致性与重放对账**：事件溯源（Event Sourcing / CQRS）、append-only 日志、确定性回放（lockstep / 定点量化），用权威事件流重放验证提议可复现性
> - **托管规则下发形态**：成熟风控 / 反作弊后台的「规则热更新、灰度、A/B、版本化」运营形态（§17），服务侧改规则不需重新发布游戏服务器
> - **传输安全形态**：序号 + nonce 防重放、握手签名、会话令牌（直接复用 network §6 crypto，不自建密码学）
> 本文为纯经典安全工程 + 确定性校验 + 可解释统计阈值路线（运动学约束、可达性查询、资源守恒、令牌桶限流、重放序号、事件流交叉对账），**不含任何 AI/ML 内容**（统计为确定性、可解释的硬阈值与计数，非机器学习，不含行为模型 / 异常检测网络 / 分类器），不含任何 Unreal / Unity / Valve / EAC / BattlEye / 其他引擎或反作弊产品的源码或衍生代码；**引擎基座与默认构建不含内核态 / 驱动级 / ring-0 组件**（内核态仅作可选客户端加固档 Tier 2：opt-in、feature + 平台门控、信号一律软、安全根不下放；第一方加固模块 `pac_hardening` 暂列 TODO 待设计，当前仅经第三方 provider 接入，见 §24、§25.3）。

## 1. 设计哲学与定位（为什么反作弊是独立服务、不进引擎 `pkg/`）

反作弊与引擎其它子系统有一条本质差别：**它的价值在对抗与运营，而非在渲染一帧或推进一次仿真**。渲染 / 物理 / 音频随引擎版本一同发行即可；反作弊却需要「游戏已上线后，持续改规则、追新外挂、跨局关联、运营封禁与申诉」。把它塞进引擎工作区 `pkg/` 会带来三重错配：

- **发行节奏错配**：引擎按版本稳态发行，反作弊要能「今天发现新作弊，今天下发新规则」。绑在引擎版本里，改条阈值都要重编重发整个引擎——致命的运营延迟。
- **职责与信任错配**：引擎是「所有接入者共享的通用底座」；反作弊是「带对抗性、带运营后台、带数据合规、可能分级收费」的产品。二者的信任面、合规面、商业面都不同，强行同仓会污染引擎的中立性。
- **成本与形态错配**：深度对账、跨局关联、封禁编排是**重算 + 有状态 + 可计费**的服务侧工作，天然该独立部署、独立计量，而不是编译进每个游戏服务器二进制里。

因此 Prism 把反作弊**从引擎切出去**：

- 引擎工作区 `pkg/` 只留一个东西——接缝 `prism_net_acheat_api`（network 侧，trait + 钩子上下文 + 默认 no-op，network §4 / §20）。它零依赖、零成本、永远存在。
- 反作弊**独立成仓、独立版本、独立发行**（self-hosted 或托管云，**可能收费**），实现接缝背后的 provider。引擎不 `path`/`git` 依赖它；集成方按需以外部依赖引入 SDK，或只把权威事件流指向托管端点。
- 对引擎与绝大多数接入者而言，「不买 / 不接反作弊」= 接缝是 no-op，**编译期整条链消失、零运行时税**（§6、§19）。

这条切分还顺带回答了「为什么能收费」：引擎开源 / 随引擎免费的是**接缝与一份参考用的本地守卫**；**可收费的是服务侧的重活与运营价值**——托管深审算力、跨局 / 跨服 / 跨作品关联、规则托管热更新、封禁编排与申诉工作流、运营看板与 SLA（§21）。收费点与架构分层天然对齐，而非硬塞的商业开关。

**可选加固档（借形态不照搬实现）**：内核态 / 驱动级 / ring-0、内存扫描 / 反调试 / 进程保护仅作**可选客户端加固档**（Tier 2，§25.3）——默认不含、opt-in、feature + 平台门控、信号一律软、安全根不下放；借鉴 EAC / BattlEye / Riot Vanguard / 腾讯 ACE 的客户端加固**形态**，第一方实现 TODO 待设计，当前仅经第三方 provider 接入（§16、§24）。
**不照搬**：不把客户端检测结果当安全根（可破解，仅作噪声过滤 / 软信号）；不引入任何 AI/ML 行为检测、异常检测网络或分类器（§13、§24）；不靠保密校验逻辑获得强度；不把反作弊塞进引擎工作区绑死发行节奏（§1）。

## 3. 部署与集成形态（embedded SDK / sidecar / 托管云）

同一套接缝（§5）、同一套快路径 / 深路径分离（§4），对应三种部署形态。集成方按安全需求、运维能力与预算选择，**切换形态不改游戏代码**：

| 形态 | 快路径（硬拒绝） | 深路径（对账 / 计分 / 编排） | 典型场景 | 商业 |
|---|---|---|---|---|
| **embedded SDK** | 进程内守卫（链接进游戏服务器） | 同进程异步任务（`prism_tasks` 后台） | 自建运维、单服 / 小规模、数据不出域 | 库授权 / 免费参考档 |
| **sidecar** | 进程内守卫 | 同主机 / 同机房独立进程，消费权威事件流 | 中大规模、深审与游戏逻辑资源隔离 | 自托管服务 |
| **托管云（managed）** | 进程内守卫（规则由云端热推，§17） | 厂商托管后端（跨局关联 / 看板 / 封禁 / 申诉 / SLA） | 大规模竞技、免运维、要跨服关联 | **收费（SaaS / 计量）** |

共同点（三形态不变量）：

- **快路径永远在进程内**：无论深路径在哪，同步硬拒绝（`on_proposal` / `on_rate` / `on_lagcomp`）**绝不做网络往返**——它由链接进游戏服务器进程的守卫以本地规则表直接判定（§4、§9）。深路径再远，也不拖慢权威 tick。
- **深路径消费权威事件流**：深审 / 计分 / 审计只消费 network 的权威事件流与审计流（§8、§10、network §18 replay），是**只读、latency-tolerant、可抽样**的——因此可以安全地放到 sidecar 或托管云，而不触碰 tick 热路径。
- **接缝一致、形态可迁移**：embedded → sidecar → managed 是**部署选择而非代码分叉**；接缝 trait（§5）在三形态下签名一致，迁移只改配置与 provider 注册（§16）。
- **离线 / 单机优雅降级**：深路径不可达（断网 / 云故障）时，快路径守卫**仍以最后一次下发的规则表本地运行**，深审转为本地缓冲 / 稍后补算；安全不塌、只是暂时失去跨局关联与实时看板（§17 的降级契约）。

> 三形态的吞吐、深审延迟、跨局关联时效均为 design target，本机无多端 / 多服实测环境，如实标注。

## 4. 快路径 / 深路径分离架构（本地守卫 vs 异步服务侧深审）

这是本次重构的架构骨架，也是「独立服务」能同时满足「低延迟」与「重运营」的关键。把反作弊的全部工作沿**延迟敏感度**切成两条路径：

```text
游戏服务器进程(权威 tick 热路径)
  │  每条上行提议 / 速率事件 / 回溯请求
  ▼
┌─────────────── 快路径: 进程内守卫(fast-path guard) ───────────────┐
│ no_std + alloc, O(1)~O(log n), 零堆分配, 绝不网络往返             │
│  · on_proposal  运动学/可达/交互/资源守恒 硬规则 → Accept/Reject/Soft │
│  · on_rate      令牌桶/漏桶/滑窗 → Allow/Throttle/Drop              │
│  · on_lagcomp   回溯 tick 与输入序号自洽 → Accept/Reject            │
│ 规则表来自深路径下发(§17), 本地常驻, 断网也能跑                      │
└───────────────┬──────────────────────────────┬────────────────────┘
         Reject(挡下,不定序)              Soft/事件(入权威事件流)
                │                                │ 异步, 只读, 可抽样
                ▼                                ▼
          (提议从未成为真相)        ┌──── 深路径: 异步服务侧深审 ────┐
                                   │ std + tokio, 同进程/sidecar/托管云 │
                                   │  · on_tick_audit 确定性对账重放    │
                                   │  · 计分聚合 + 可解释硬阈值(§13)     │
                                   │  · 跨局/跨服关联(§10)              │
                                   │  · 处置编排 + 封禁 + 申诉(§14)      │
                                   │  · 审计落盘 + 举报回放(§15)         │
                                   │  · 规则热更新下发回快路径(§17)      │
                                   └────────────────────────────────────┘
```

设计要点：

- **快路径只做「本地能确定的硬判定」**：物理不可能（瞬移 / 穿墙 / 超速）、协议滥用（洪泛）、回溯自洽——这些不需要全局视野、不需要重放，`O(1)~O(log n)` 本地即可裁决，且**硬拒绝的提议直接不定序（network §14.2），等价于从未发生**。这是最强也最省的一招，必须在热路径同步完成。
- **深路径做「需要视野 / 需要重放 / 需要跨局」的重活**：确定性对账要重放一段事件流（§10），跨局关联要聚合多会话 / 多账号（§10），计分 / 处置 / 封禁 / 申诉是有状态运营流程（§14）——全部 latency-tolerant、可抽样、可排队，放异步服务侧，不碰 tick。
- **规则下发闭环**：深路径是「大脑」，持续产出 / 更新规则表与阈值，**热推**给快路径守卫（§17）；快路径是「反射弧」，拿着最新规则表本地快判。大脑可以在托管云、反射弧永远在本地——这正是「独立甚至远程的服务」不伤手感的根本原因。
- **故障域隔离**：深路径崩了 / 断网了，快路径照常本地运行（用最后一次规则表）；快路径的误配不会把深审拖垮（二者经有界队列解耦）。安全强度退化是渐进的，不是断崖的（§3 降级契约）。
- **与 network 契约对齐**：这条分界线正是 network §14.2「钩子是同步判定、异步重活」契约的落地——`on_proposal` / `on_rate` / `on_lagcomp` 同步走快路径，`on_tick_audit` 异步走深路径（§8）。

> 快路径每提议开销、深路径对账吞吐与下发时效均为 design target；可验证部分限快路径规则求值 / 令牌桶 / 自洽校验与深路径对账判定的纯函数单测（§19、§20）。

## 5. 服务与引擎的边界：接缝契约（seam 在 `pkg/`、service 独立仓）

引擎与反作弊服务之间只有**一条窄接缝**，这条缝是二者唯一的编译期契约：

```text
引擎工作区 pkg/ (随引擎发行, 零成本)
  prism_net_acheat_api        反作弊接缝: AntiCheatProvider trait + 钩子上下文类型
                              + 默认 no-op 总装(network §4/§20)
                              不依赖任何反作弊实现; 不开 anticheat feature 即编译期移除

────────────────── 接缝边界(trait, 运行时注入) ──────────────────

反作弊独立仓库 prism_anticheat/ (独立版本/发行, 可能收费, 不在 pkg 下)
  pac_guard        快路径守卫: no_std+alloc, 规则表求值/令牌桶/自洽校验(§4、§9)
  pac_core         纯逻辑: 对账判定/计分器/规则 DSL 求值(可脱网单测)
  pac_recon        深路径对账: 权威事件流重放交叉验证(消费 network replay §10)
  pac_rate         限流配额: 令牌桶/漏桶/滑窗(§11)
  pac_score        计分裁决: 确定性计数聚合 + 可解释硬阈值(无 ML, §13)
  pac_enforce      处置编排: flag/throttle/kick/ban/影子 + 申诉回滚(§14)
  pac_audit        审计: append-only 日志 + 举报回放(接 prism_diagnostic §15)
  pac_correlate    跨局/跨服关联: 多会话确定性聚合(§10)
  pac_service      服务宿主: sidecar/托管后端, 事件流消费 + 下发闭环(§4、§17)
  pac_sdk          集成 SDK: 把 pac_guard + 事件流接线封装成一行接入(§18)
  pac_provider_3p  第三方商用适配: 其信号降级为软信号(§16、§24)
  pac_managed      托管客户端: 规则热推/遥测上报/封禁同步(§17、§21)
  pac_launcher     启动器/引导: 服务端 supervisor(装配快深路径/验签加载规则表/健康检查/
                   热重载编排/优雅降级监督, Tier0) + 客户端 bootstrap(薄, 仅会话引导+软信号, Tier1)(§25)
  pac_hardening    [TODO 待设计] 可选客户端加固层(Tier2): 内核态能力槽, 独立分发,
                   feature(hardening)+平台双门控, 信号一律软, 安全根不下放;
                   第一方实现未设计, 当前经 pac_provider_3p 接第三方(ACE/EAC/Vanguard)(§24、§25.3)
```

契约要点：

- **引擎只认 trait，不认实现**：`prism_net_acheat_api` 定义 `AntiCheatProvider`（总装）、各钩子上下文、裁决枚举与默认 no-op。它在引擎工作区，随引擎发行，**零依赖反作弊服务**。
- **服务独立成仓、独立版本**：`prism_anticheat/` 是另一个 Cargo 工作区 / 另一个仓库，有自己的版本号与发行节奏（§22 版本解耦）。集成方按需以外部依赖引入 `pac_sdk`（embedded / sidecar），或只配置事件流端点（managed）。
- **注入而非内联**：游戏服务器启动时把一个 `AntiCheatProvider` 实现注册进 network 接缝（§6、§16）；不注册 = no-op。network 不 `path` 依赖反作弊仓，反作弊仓依赖 network 的接缝类型（单向，§network §20 一致）。
- **快路径可链接、深路径可远程**：`pac_guard` 是 `no_std + alloc`、可编译进游戏服务器进程的小库；`pac_service` 等是 `std + tokio` 的服务侧，可同进程、可 sidecar、可托管云（§3、§4）。接缝签名在三形态下一致。
- **引擎中立性**：引擎工作区里**不存在任何 `pac_*` crate**，也不 vendor 反作弊代码；引擎的 CI / 发行 / 开源边界不被反作弊的对抗性与商业性污染（§1）。


## 6. 档位化与 provider 模型（可替换 / 可组合 / 热替换）

从引擎视角看，整个反作弊服务只是接缝背后的**一个 provider**；从服务侧看，内部又分成若干可组合、可替换的子 provider。两级可替换性合在一起，才是「模块化」的完整含义：对引擎——服务整体可被官方 / 第三方 / 自定义 / no-op 替换；对服务——每项校验、计分、处置、审计都可逐项替换。

反作弊按部署场景分档，每档都是「选择并组合 provider」的结果，而非独立代码路径：

| 档位 | 典型场景 | provider 组合 | 开销 |
|---|---|---|---|
| `off` | 单机 / 纯本地 | no-op（编译期移除） | 零 |
| `trusted` | 可信局域网 / 内部测试 | 仅会话完整性（§12），不开约束校验 | 极低 |
| `standard` | 常规在线合作 / 轻竞技 | 会话完整性 + 提议约束校验（§9）+ 限流（§11） | 低（仅快路径） |
| `competitive` | 竞技 / 排位 | standard + 确定性对账（§10）+ 计分（§13）+ 审计（§15） | 中（快 + 深路径） |
| `hardened` | 高价值竞技 / 防刷经济 | competitive + 跨局关联（§10）+ 资源守恒强审计 +（可选）客户端加固 Tier 2（§25.3，经第三方 provider、信号软、安全根不下放） | 中高（深路径为主） |

档位只是**默认 provider 集的预设**，并与快路径 / 深路径分层（§4）天然对齐：`off`/`trusted`/`standard` 基本只用快路径（本地、无服务侧算力），`competitive`/`hardened` 才引入深路径（对账 / 计分 / 关联，可独立计费，§21）。核心机制：

- **provider = trait + 默认实现**：接缝 `AntiCheatProvider`（总装，在 `prism_net_acheat_api`，§5）聚合若干 `CheckProvider`（单项校验）、`ScoringProvider`（计分）、`EnforcementProvider`（处置）、`AuditSink`（审计）；服务侧 `pac_*` 提供这些 trait 的默认实现，可逐项替换。
- **可注册、可组合**：集成方可注册多个 `CheckProvider` 并声明优先级与短路策略（任一硬拒绝即短路，软信号累加入计分，§8）。
- **可热替换**：provider 注册表支持运行时切换（如灰度上线新规则、A/B 对比阈值），切换是事务性的、不丢审计流（§16、§17）。
- **feature 门控**：`anticheat` 关闭则接缝总装退化为 no-op；服务侧单项 feature（`check_motion` / `reconcile` / `rate_limit` / `telemetry` / `audit_log` / `correlate` / `provider_3p` / `managed` / `hardening`，`hardening` 另需平台门控、默认关闭）可独立裁剪。

## 7. 信任与威胁模型（攻击面分类）

反作弊的第一步是明确「什么可信、什么不可信、要防什么」。Prism 的信任边界由 network 根基决定（network §14.1）：

- **可信**：权威服务器进程、权威仿真结果、权威事件流、服务器侧 persist 事务。它们是安全根。
- **半可信**：传输通道（可被窃听 / 篡改 / 重放，但 network §6 crypto 提供完整性与重放防护，使篡改 / 重放可检测）。
- **不可信**：客户端进程、客户端内存、客户端渲染、客户端上行的一切「结果声明」。客户端只被允许上行**输入与提议**，绝不被允许上行「我造成了什么结果」（network §9、§14.1）。

威胁分类与对应防线：

| 威胁类别 | 典型手段 | 主防线（本文） | 兜底 |
|---|---|---|---|
| 运动作弊 | 瞬移 / 加速 / 穿墙 / 飞天 | 运动学与可达性约束校验（§9，快路径） | 对账重放不复现则拒绝（§10，深路径） |
| 命中作弊 | 自瞄 / 扩大判定 / 回溯滥用 | 回溯 tick 与输入序号自洽校验（§8、§12）、服务器权威判定 | 命中率统计阈值（§13） |
| 本地内存 / 注入 | 同机读写进程内存 / 注入 / 本地脚本 hook | 结构性不下发玩家不该知道的数据（network AOI / 遮挡复制） | 行为统计（§13）+（可选）客户端加固 Tier 2 抬高成本（§25.3，信号软） |
| 资源作弊 | 刷道具 / 复制物品 / 负数绕过 | 资源进出账守恒校验（§9） | persist 事务回放审计（§10、§15） |
| 协议滥用 | 洪泛提议 / RPC 风暴 / 订阅轰炸 | 速率限制与配额（§11，快路径） | 连接级熔断、临时节流（§14） |
| 重放篡改 | 重放旧包 / 伪造序号 | 序号 + nonce + 会话令牌（§12，复用 network） | 握手签名校验失败即断连 |
| 自动化 | 脚本 / 宏 / 农场 | 可解释统计阈值 + 计分（§13，深路径） | 跨局关联（§10）、处置分级（§14） |
| 跨局 / 跨服作弊 | 多账号协同 / 换服规避 / 工作室农场 | 深路径跨局关联 `pac_correlate`（§10） | 账号级处置与证据链（§14、§15） |

**关键**：威胁模型、规则、阈值全部公开可审计；强度来自结构（服务器权威 + 确定性对账），不来自「检测逻辑不被逆向」（§24 不靠保密）。

## 8. 接入网络权威回路：钩子点契约（对接 network §14.2）

反作弊通过 network 暴露的五个钩子点插入权威回路。本节是**契约**：规定每个钩子被调用的时机、上下文、provider 可返回的裁决、以及对网络时序的约束。它与 §4 的快 / 深路径分层严格对齐——**同步钩子只走快路径（进程内守卫 `pac_guard`），异步钩子喂深路径（服务侧 `pac_service`）**。

| 钩子 | 调用时机（network） | 上下文入参 | provider 可返回 | 路径 / 时序约束 |
|---|---|---|---|---|
| `on_proposal` | 每条上行提议定序前（net §7.1） | 连接 id、提议体、上一权威态引用、tick | `Accept` / `Reject(reason)` / `Soft(signal)` | **快路径**：O(1)~O(log n)、零堆分配、不得网络往返、在 tick 预算内 |
| `on_tick_audit` | 每权威 tick 结束后（net §9） | 本 tick 已应用事件、权威态快照句柄 | `Vec<Signal>`（计分） | **深路径入口**：仅派发事件给异步侧，不在热路径同步阻塞 |
| `on_rate` | 每连接提议 / RPC / 订阅变更（net §15） | 连接 id、动作类别、时间戳 | `Allow` / `Throttle` / `Drop` | **快路径**：O(1) 令牌桶查询 |
| `on_lagcomp` | 延迟补偿回溯前（net §11） | 回溯 tick、输入序号、客户端声明时刻 | `Accept` / `Reject` | **快路径**：O(1) 自洽校验 |
| `on_enforce` | 命中阈值 / 规则时（本文触发） | 连接 id、累计计分、命中规则 | 处置动作（§14） | **深路径产出 → 回灌**：异步裁决，可排队 |

契约不变量：

- **同步快路径、异步深路径**：`on_proposal` / `on_rate` / `on_lagcomp` 在权威热路径内，由本地 `pac_guard` 用常驻规则表求值，必须有界且快，**绝不发起网络往返**（断网也能跑，§4）；`on_tick_audit` 只把权威事件流派发给深路径，对账 / 计分 / 审计落盘全异步（§19），不拖慢 tick。
- **拒绝即不定序**：`on_proposal` 返回 `Reject` 的提议**不进入权威事件流**，等价于「从未发生」，不产生 delta、不广播、不入存档。这是反作弊最强的一招——作弊提议在成为真相之前就被挡下。
- **软信号不改变结果**：`Soft(signal)` 不拒绝提议（避免误判伤害正常玩家），只累加入计分（§13），由计分阈值在 `on_enforce` 统一裁决。
- **上下文足够、策略自持**：network 保证钩子被「按时、带足够上下文」调用（network §14.3）；具体阈值、规则、处置全在服务侧 provider，network 不实现策略。
- **可裁剪**：任一钩子对应的 provider 可为 no-op，编译期移除。

## 9. 提议约束校验（快路径硬规则：运动学 / 物理 / 交互 / 资源守恒 / 可达性）

这是 `on_proposal` 的主力，**全部在快路径 `pac_guard` 内完成**：在提议定序前，用常驻规则表以**确定性硬规则**判定提议是否物理 / 逻辑上可能。全部是可解释阈值，无任何学习，零堆分配、不触网络。

**运动学约束**：

- **速度上限**：`|Δpos| / Δt ≤ v_max(实体类/状态)`，`v_max` 来自 gameplay 配置（走 / 跑 / 载具 / 技能位移各有上限）。定点量化计算（`prism_math`），跨平台一致。
- **加速度与跃变**：相邻 tick 速度变化 `≤ a_max`，防瞬时速度脉冲；位置跃变（teleport）必须由权威事件产生，客户端提议的瞬移一律拒绝。
- **垂直约束**：无飞行能力的实体，竖直位移受重力与地面约束，防飞天。

**可达性校验（查 world）**：

- 提议的新位置到旧位置的路径不得穿越 world 碰撞体（查 `prism_world` 几何 / 碰撞）；一次校验用「胶囊扫掠 / 射线」近似，开销有界。
- 交互目标必须在可达范围与视锥 / 遮挡约束内（反穿墙拾取 / 穿墙攻击）。

**交互约束**：

- **距离与冷却**：交互 / 攻击 / 拾取的距离 `≤ range_max`，冷却 `≥ cooldown_min`，防超距与超频。
- **目标有效性**：交互目标必须在提议方 AOI 内且处于可交互状态（防操作不可见 / 不可交互对象）。

**资源守恒**：

- 任何资源变动（货币 / 道具 / 弹药 / 耐久）必须进出账守恒：`Σ产出 - Σ消耗 = ΔC`，差额对不上即拒绝。
- 禁负绕过：数量不得为负、不得整型回绕；上限溢出检测。
- 复制 / 制造 / 交易走权威事务（scene override delta、network §7），客户端只提议、不记账。

校验结果：硬违反 → `Reject`（提议不定序）；临界 / 可疑但不确定 → `Soft(signal)`（计分，§13）。阈值与规则由 `CheckProvider` 持有，可替换 / 可按 gameplay 配置化；规则表由深路径热推、本地常驻（§17）。

## 10. 确定性对账审计（深路径事件流重放交叉验证 + 跨局关联）

对账是 `on_tick_audit` 下游、**深路径 `pac_recon` 的主力**，也是反作弊最硬的判据：**用权威事件流重放，验证「客户端提议能否在权威仿真中复现」**。它天然 latency-tolerant、只读、可抽样，正是该放到异步服务侧（可同进程 / sidecar / 托管云）的重活。

原理（复用 network §13 的确定性回放与 persist 事件流语义）：

- 权威仿真是**确定性**的（定点量化、固定步长、Lamport 定序，network §21、§13）。给定相同初态 + 相同输入序列，必然得到相同结果。
- 对账器定期（或按抽样 / 按可疑连接）取一段权威事件流，在影子仿真里重放，比对「客户端提议声称达成的态」与「权威重放实际达成的态」。
- **不复现即作弊证据**：若客户端提议只有在违反物理 / 规则时才能达成当前态，重放会暴露不一致——这是比单帧阈值强得多的判据。

**跨局 / 跨服关联（`pac_correlate`，深路径）**：单局对账抓「这一局里不可能的事」，跨局关联抓「跨越多局 / 多服才暴露的事」——同一账号 / 设备指纹 / 行为签名在多会话中的一致异常、工作室农场的协同模式、换服规避。关联是**确定性聚合**（计数、集合交并、时间窗关联），**非 ML**（§13、§24）；它天然有状态、重算、可计费，是托管深审的核心价值之一（§21）。

工程要点：

- **抽样而非全量**：全量对账开销高，默认对**可疑连接（计分超软阈值）**与**随机抽样**做对账，竞技档可提高抽样率（§6）。开销预算见 §19。
- **异步批处理**：对账在服务侧后台批处理（可借 `prism_tasks` 或服务自有运行时），不占权威 tick 热路径；结果以 `Signal` 回灌计分。
- **确定性前提**：参与权威的浮点必须定点化（network §21、§7），否则重放不收敛、对账失效。本文把「权威路径定点化」列为硬前提。
- **复用而非另建**：对账直接复用 network 的事件流录制 / 回放基建（net §18 replay）；若服务侧需要跨进程 / 跨机的持久事件流，可选以 `uwu_event_mesh` 作权威事件流的 durable 后端（仅服务端 `feature evmesh`，network §5.1），而非自建第二套日志。

对账产出进入审计日志（§15），可用于举报复盘与封禁证据链——每条处置都能回放到「哪条提议、在哪 tick、与权威重放的哪处不一致」。

## 11. 速率限制与配额（反 DoS / 洪泛）

`on_rate` 防的是「不靠单条非法提议、而靠海量合法形状提议压垮服务器或刷量」的攻击，**全部在快路径 `pac_rate` 内 O(1) 完成**：

- **令牌桶 / 漏桶**：每连接、每动作类别（提议 / RPC / 订阅变更 / 聊天 / 交易）独立令牌桶，`O(1)` 查询。超速 → `Throttle`（排队降速）或 `Drop`（丢弃并计分）。
- **分层配额**：连接级、玩家级、IP / 会话级（部署环境提供）分层限额，防单连接刷爆与多连接分布式刷。
- **滑窗计数**：对低频高价值动作（交易 / 制造 / 举报）用滑动窗口计数，防慢速刷量。
- **自适应降级**：服务器过载时（接 network §15 带宽 / CPU 预算调速），限流阈值自适应收紧，优先保权威 tick 稳定——**降级而非崩溃**。
- **熔断**：持续超限的连接触发连接级熔断（临时节流 → 断连），走 `on_enforce`（§14）。

限流配额全部是确定性计数器，可单测、可复盘、无学习，断网 / 脱离深路径仍完整生效。

## 12. 会话完整性与重放防护（复用 network crypto）

反作弊**不自建密码学**，直接复用 network §6 的会话安全：

- **序号 + nonce 防重放**：每包单调序号 + nonce，重放旧包 / 乱序伪造在传输层被 network 检测丢弃；反作弊在 `on_proposal` 额外校验提议序号与权威 tick 的自洽（防「合法包但语义重放」）。
- **握手签名与会话令牌**：连接建立时的握手签名、会话期令牌由 network 维护；令牌失效 / 签名不符 → network 断连，反作弊不另处理。
- **回溯自洽（`on_lagcomp`）**：延迟补偿允许服务器回溯到「客户端所见时刻」判定命中（network §11）。反作弊校验客户端声明的回溯 tick 与输入序号自洽、落在有界回溯窗口内——防「谎报更早时刻以获得不公平回溯命中」。
- **完整性不等于可信**：传输完整性只保证「包没被中途篡改 / 重放」，**不保证内容为真**。内容为真仍由服务器权威与提议校验（§9、§10）保证。这条边界必须清楚：crypto 防中间人与重放，不防「客户端自己说谎」——后者靠权威。

## 13. 统计阈值与计分（确定性、可解释、无 ML）

确定性校验（§9、§10）能挡下「物理不可能」的作弊，但有灰区——比如统计上异常但单帧合法的行为（命中率偏高、移动模式机械）。这里用**可解释统计阈值 + 计分聚合**（深路径 `pac_score`），而非机器学习。

**硬性立场：无任何 AI/ML。** 不含行为模型、异常检测网络、分类器、嵌入或任何训练式判别。所有统计都是：

- **确定性计数器**：命中率、拒绝率、交互频率、移动一致性、资源进出比等，按固定窗口聚合，纯计数。
- **可解释硬阈值**：每个计数器对应人类可读的阈值与权重（如「命中率 > X% 持续 N 分钟 → +W 分」），阈值由集成方配置、可审计、可复盘，并随规则表热更新（§17）。
- **计分聚合**：各 `CheckProvider` 的软信号（§8 `Soft`）、对账不一致（§10）、跨局关联信号（§10）加权累加成连接 / 账号计分；计分跨阈值触发 `on_enforce`（§14）。
- **带滞回与衰减**：计分有衰减（避免历史噪声永久累积）与滞回（避免在阈值附近抖动反复处置），参数确定、可解释。

为什么拒绝 ML：误判在反作弊里代价极高（误封正常玩家），而 ML 判据**不可解释、不可复盘、不可向被封玩家举证**；且 ML 需要训练数据与持续对抗调参，是军备竞赛黑洞。Prism 选择「可解释硬阈值 + 确定性对账证据链」，每次处置都能回放到具体提议与具体规则（§10、§15）。

## 14. 处置动作分级（flag / throttle / kick / ban / 影子 / 遥测 / 申诉）

`on_enforce` 的处置是**分级、可组合、可回滚**的（深路径 `pac_enforce`），匹配「误判代价」与「漏判代价」：

| 动作 | 触发档 | 效果 | 可逆性 | 适用 |
|---|---|---|---|---|
| `telemetry` | 任意软信号 | 仅记录遥测，不影响玩家 | — | 持续观测、调阈值 |
| `flag` | 低计分 | 标记连接、提高抽样对账率（§10） | 完全可逆 | 可疑但不确定 |
| `throttle` | 协议滥用 / 中计分 | 降速 / 排队 / 限配额（§11） | 完全可逆 | 洪泛、超频 |
| `shadow` | 中高计分 | 影子处理：作弊效果本地可见、权威侧不生效 / 隔离匹配 | 可逆 | 高疑未实锤，降低对抗反馈 |
| `kick` | 高计分 / 硬违反累积 | 断开本次会话 | 会话级 | 明确违规、即时止损 |
| `ban` | 对账实锤 / 极高计分 | 账号 / 会话封禁（时长分级 / 永久） | 可申诉回滚 | 确定性证据链支撑（§10、§15） |

处置原则：

- **硬拒绝优先于处置**：能在 `on_proposal` 直接 `Reject` 的（§9），根本不需要处置——作弊提议没成为真相。处置是对「已累积可疑」的连接的裁决。
- **确定性证据链支撑重罚**：`ban` 级处置必须有对账证据链（§10）或硬违反记录（§9），可回放、可向玩家举证、可申诉回滚。纯统计阈值（§13）默认最高只到 `shadow` / `kick`，不单独支撑永久封禁——避免 ML 式不可解释误封。
- **误判可回滚**：所有处置写审计日志（§15），错误处置可撤销并恢复；计分带衰减与申诉通道。
- **分批与影子**：对实锤作弊可延迟 / 分批封禁（降低作弊者定位检测规则的能力），影子处置降低即时对抗反馈——借多数 AAA 形态（§2）。
- **处置是 provider**：`EnforcementProvider` 可替换（集成方自定义处置矩阵、接运营后台），默认实现提供上表动作；托管形态下处置编排与申诉工作流由服务侧统一提供（§21）。

## 15. 遥测、举报与审计日志（接 `prism_diagnostic`）

反作弊的可观测性与证据链接入 `prism_diagnostic`（快路径遥测）与服务侧审计后端（深路径审计 `pac_audit`），不自建第二套诊断：

- **遥测计数器**：各校验的拒绝率、软信号率、对账抽样命中率、限流丢弃率、处置分布，作为 `prism_diagnostic` 计数器导出，可实时看板与告警。
- **审计日志（append-only）**：每条硬拒绝、每次对账不一致、每次处置都写 append-only 审计日志（借事件溯源形态），含「连接 id、tick、提议摘要、命中规则、规则版本、证据引用」。日志可导出、可离线复盘；托管形态下集中归集并支撑运营看板与 SLA（§21）。
- **举报回放**：玩家举报或自动 flag 的连接，可取其权威事件流片段做确定性回放复盘（§10，复用 network §18 replay），人工或运营可逐 tick 看「发生了什么、哪条提议异常」。
- **可解释证据链**：因为判据是确定性对账 + 可解释阈值（§10、§13），每次处置都能回放举证——这是拒绝 ML 换来的核心运营优势。
- **隐私边界**：审计日志只记录游戏内权威状态与提议摘要，**不采集客户端进程 / 内存 / 系统信息**（§24 硬边界）；PII 处理遵循部署侧合规，数据边界见 §21，设计只定接缝不越权。

`audit_log` 与 `telemetry` 为可选 feature，可按部署裁剪。

## 16. provider / 服务契约与可替换性（官方 / 第三方 / 自定义 / no-op）

可替换性分两级（§6）。**第一级：整个服务即一个 provider**——从引擎接缝看，`AntiCheatProvider` 的实现可整体换成官方服务、第三方商用服务、集成方自定义，或 no-op（可信局域网 / 单机），迁移不改游戏代码（§4、§5）。**第二级：服务内部逐项 provider**：

| provider | 职责 | 默认实现（`pac_*`） | 可替换为 |
|---|---|---|---|
| `AntiCheatProvider` | 总装：聚合各 provider、分发钩子、裁决 | `pac_service` 总装 | 官方 / 第三方商用总装、自定义、no-op |
| `CheckProvider` | 单项提议校验（§9） | `pac_guard` 运动 / 可达 / 交互 / 资源守恒 | 自定义规则、gameplay 专用校验 |
| `ScoringProvider` | 计分聚合与阈值（§13） | `pac_score` 确定性计数 + 硬阈值 | 自定义权重 / 阈值矩阵 |
| `EnforcementProvider` | 处置执行（§14） | `pac_enforce` 分级处置矩阵 | 接运营后台、自定义处置 |
| `AuditSink` | 审计落盘（§15） | `pac_audit` 接 `prism_diagnostic` | 自定义日志后端、外部 SIEM |

契约要点：

- **零配置可跑**：默认 provider 全部零配置可用，替换是 opt-in；不注册任何实现 = no-op，编译期整条链消失（§5、§19）。
- **可注册、可组合**：多个 `CheckProvider` 按优先级注册，硬拒绝短路、软信号累加（§8）。
- **可热替换**：provider 注册表运行时切换是事务性的，不丢审计流、不中断权威 tick——支持灰度与 A/B 调参（§17）。
- **第三方集成只走接缝**：商用反作弊（`provider_3p` feature，`pac_provider_3p` 适配）通过接缝接入，其**服务器可验证的信号降级为软信号**（计分，不作硬拒绝唯一依据）。其**客户端内核态组件**仅作**可选加固档**（Tier 2，§25.3）由第三方承担与分发，Prism 侧不内联、信号一律软、安全根不下放；第一方加固模块 `pac_hardening` 暂列 TODO 待设计（§24）。
- **服务版本独立于引擎**：provider 实现随反作弊服务独立发行，引擎只认接缝类型；接缝版本与服务版本解耦（§22）。

## 17. 托管规则热更新与灰度（易维护：改规则不重发游戏服务器）

这是「反作弊必须独立于引擎发行」的直接工程体现，也是易维护性的核心（§1）。作弊对抗是**天级 / 小时级**的运营节奏，而游戏服务器重编重发是**周级 / 版本级**的节奏——两者绝不能绑死。因此规则（阈值 / 权重 / 校验开关 / 对账抽样率）是**数据而非代码**，由深路径托管下发、快路径常驻求值（`pac_managed`）：

- **规则表即数据**：`pac_guard` 的快路径求值器消费一张版本化的规则表（确定性 DSL / 配置，非可执行代码），改阈值 = 下发新表，不重编游戏服务器。
- **热推 / 灰度 / A-B**：新规则可按比例灰度（如 1% → 10% → 100%）、按分组 A/B（对比两套阈值的误报 / 命中），全程遥测对比（§15），确认无误伤再全量。
- **版本化与可回滚**：每张规则表有版本号；审计日志记录「用哪个版本判定」（§15、§22）；发现误伤可一键回滚到上一版本，历史处置可按当时规则复盘。
- **下发闭环**：深路径（托管或 sidecar）→ 签名的规则表 → 游戏服务器内 `pac_guard` 验签加载 → 生效回执 → 看板确认。规则表经 network crypto 签名（§12），防中间人篡改下发。
- **降级契约**：下发链路中断 / 深路径不可达时，`pac_guard` **继续用最后一次成功加载的规则表运行**（§4 离线优雅降级），绝不因「拉不到新规则」而放行或崩溃；恢复后增量追平。

一句话：**改规则像改配置，不像发版本**——这是独立服务相对「反作弊编进引擎」的决定性运营优势。

## 18. 接入易用性与集成工作流（SDK / 零配置 / 单机不分叉）

易用性目标：**单机 / 可信环境零感知、在线接入一行、从 embedded 到 managed 迁移不改游戏代码**。

- **零配置 no-op**：不开 `anticheat` feature，接缝即 no-op，编译期移除，单机 / 原型开发**完全无感、零税**（§5、§19）。
- **一行接入（`pac_sdk`）**：在线项目通过 SDK 把「快路径守卫 `pac_guard` + 深路径事件流接线」封装成一次注册调用，默认 provider 全部零配置可用（§16）；集成方只需在游戏服务器启动时 `register(AntiCheat::standard())` 一类调用。
- **prelude 导出**：SDK 提供 `prelude`，一次性导入接缝 trait、档位预设、常用处置与遥测订阅，减少样板。
- **单机不分叉**：同一套游戏代码，单机跑 no-op、联机跑 standard、竞技跑 competitive，差异只在**启动时选哪个档位 / provider**，而非两套代码路径（§6）。
- **三形态迁移无痛**：embedded SDK（库链接进游戏服务器）→ sidecar（同机独立进程）→ managed（托管云）切换，只改「深路径端点配置」，接缝签名与游戏调用不变（§3、§4）。先用 embedded 起步，规模化后平滑迁到 sidecar / managed。
- **可脱网开发与测试**：`pac_core` / `pac_guard` 纯逻辑可脱网单测（喂历史提议即可），本地无需起深路径即可开发与验证快路径规则。
- **可观测即可调**：接入即有 `prism_diagnostic` 遥测看板（§15），阈值调参有数据支撑，不靠猜。

## 19. 性能与开销预算（快路径 / 深路径分别预算）

全部为 design target（本机无多端对抗环境，如实标注）。关键是**快 / 深路径分别立预算**（§4），互不污染：

**快路径（进程内 `pac_guard`，在权威 tick 预算内）**：

- **`on_proposal`**：每条提议约束校验目标 `O(1)~O(log n)`，含一次可达性近似查询（胶囊扫掠 / 射线），**零堆分配、绝无网络往返**，控制在权威 tick 预算内；超预算的校验下沉到深路径对账（§10）。
- **`on_rate` / `on_lagcomp`**：`O(1)` 令牌桶 / 自洽校验，可忽略。
- **规则表加载**：热更新为后台异步加载 + 原子切换（§17），不阻塞 tick。
- **离线无损**：深路径不可达时快路径开销与行为不变（用最后规则表，§4、§17）。

**深路径（异步服务侧 `pac_service` / `pac_recon` / `pac_score` / `pac_correlate`，latency-tolerant）**：

- **对账（§10）**：异步批处理、抽样执行。默认只对可疑连接 + 随机抽样，竞技档提高抽样率；对账吞吐受服务侧后台预算约束，不拖权威 tick。
- **跨局关联（§10）**：按窗口批量聚合，重算 / 有状态，天然可独立扩缩容与计费（§21）。
- **计分 / 审计**：计数聚合 `O(1)` 增量更新；审计落盘异步、批量、可丢弃降级（过载时优先保权威）。

**跨层**：

- **可裁剪即零税**：`off` / `trusted` 档（§6）不开约束校验与对账，开销趋零；单机 feature 全移除。
- **开销与档位挂钩**：集成方用档位（§6）在「安全强度」与「服务器成本」间线性调节；每档的 CPU / 内存预算是可配置上限，超限自适应降级（§11）。
- **部署形态与成本**：embedded 把深路径算力压在游戏服务器进程；sidecar / managed 把重活移出，游戏服务器只留快路径——这正是「重活可独立计费」的物理基础（§21）。

可验证的 CPU 纯函数部分（约束校验 / 对账判定 / 令牌桶 / 计分 / 关联聚合）设确定性单测与基准门槛；真实对抗效果（挡住多少真实作弊、封禁准确率）只能标 design target、靠上线后遥测（§15）复盘。

## 20. 确定性与可复现

反作弊的判据必须可复现，否则无法举证与申诉：

- **校验确定性**：运动 / 可达 / 资源校验走定点量化（`prism_math`），同输入同判定，跨平台一致。
- **对账确定性**：依赖权威仿真的确定性回放（network §21、§13）——权威路径浮点必须定点化，否则重放不收敛、对账失效。本文把「权威路径定点化」列为硬前提，非权威的渲染 / 表现层不受此约束。
- **计分 / 关联确定性**：计数器、阈值、衰减、滞回、跨局聚合全部确定性，给定相同事件序列产出相同计分与关联结论。
- **可复盘**：每条处置可回放到具体 tick、提议、规则版本（§10、§15、§17）——这是「拒绝 ML、选确定性」的直接收益。
- **规则版本化**：阈值 / 规则 / provider 组合随版本演进，审计日志记录「用哪个规则版本做的判定」，历史处置可按当时规则复盘（§17、§22）。

## 21. 商用 / 托管 / 数据边界模型（self-hosted vs managed，设计视角）

本节从**设计视角**（非销售视角）说明「为什么能分层收费、各形态的数据与计量边界在哪」，使商业形态与架构分层（§3、§4）严格对齐，而非硬塞的开关。

**免费 / 随引擎 vs 可收费**：

- **免费（随引擎 / 开源接缝）**：引擎工作区 `pkg/` 的接缝 `prism_net_acheat_api` + 一份**参考用的本地快路径守卫**（`pac_guard` 的开源基础规则）。任何人都能自建、自托管、不付费地跑一套基础反作弊。
- **可收费（服务侧重活与运营价值）**：托管深审算力（对账 / 计分 / 关联，§10、§13）、跨局 / 跨服 / 跨作品关联（§10）、规则托管热更新与灰度（§17）、封禁编排 + 申诉工作流（§14）、运营看板 + SLA（§15）。收费点 = 深路径 + 运营，与分层天然对齐。

**三形态的数据与计量边界**：

| 形态 | 快路径位置 | 深路径位置 | 数据边界 | 计量维度 |
|---|---|---|---|---|
| embedded SDK | 游戏服务器进程 | 游戏服务器进程 | 全在自有基础设施，不出域 | 不计量（self-hosted） |
| sidecar | 游戏服务器进程 | 同机 / 同网独立进程 | 全在自有基础设施，不出域 | 可选 license / 不计量 |
| managed 托管云 | 游戏服务器进程 | 托管后端（服务商） | 权威事件流摘要 / 对账证据出域到托管端 | 按会话 / 对账量 / 关联规模计量计费 |

**设计约束（无论是否收费都成立）**：

- **数据最小化**：出域的只有游戏内权威状态与提议摘要、对账证据、处置记录；**绝不包含客户端进程 / 内存 / 系统 / 外设信息**（§24 硬边界）。
- **边界可审计**：managed 形态下「哪些数据出域、保留多久、谁可访问」是明确契约，合规由部署 / 服务侧共同承担，设计只定接缝与数据面最小集。
- **可迁移、无锁定**：三形态接缝签名一致（§4），self-hosted ↔ managed 可迁移，不改游戏代码；审计 / 规则格式开放，防供应商锁定。
- **计量不侵入热路径**：计量发生在深路径（会话 / 对账 / 关联量级），**绝不**在快路径 `on_proposal` 里插入计费逻辑拖慢权威 tick。

## 22. 契约、不变量与版本化

- **契约**：对上（`prism_gameplay`）暴露约束声明 + 处置回调 + 遥测订阅；对下消费 network 钩子 / world 几何 / scene delta / ecs 列 / time tick / diagnostic 审计。反作弊**只读真相、不写真相**（§15）。
- **核心不变量**：①反作弊不是安全根，安全根是 network 的「服务器唯一权威 + 确定性对账 + 会话完整性」②客户端永不被信任，只上行输入与提议，结果只由权威仿真产生③硬拒绝的提议不进权威事件流（等价于从未发生）④软信号不改变结果、只计分⑤重罚（ban）须有确定性证据链或硬违反记录支撑⑥**引擎基座与默认服务无内核态 / 驱动级 / 内存扫描 / 反调试；内核态仅可选客户端加固档（Tier 2，§25.3），opt-in、信号一律软、安全根不下放，被绕过亦不改变①—⑤**⑦**无任何 AI/ML**，统计为确定性可解释阈值⑧反作弊是可替换 provider，但 provider 不得违反①—⑦。
- **引擎 seam 版本与服务版本解耦**：接缝 `prism_net_acheat_api` 随引擎发行、有自己的稳定版本与兼容承诺；反作弊服务 `pac_*` 独立发行、独立版本（§1、§5）。服务只能依赖接缝的**已发布稳定版本**，接缝向后兼容窗口内服务无需随引擎升级而重编；接缝破坏性变更须走弃用期，并在两侧版本矩阵中标注。
- **规则版本化**：规则 / 阈值 / provider 组合有版本号（§17），审计日志记录判定所用版本，历史处置可按当时规则复盘；校验规则随 gameplay 配置与 scene / persist 稳定字段演进。
- **feature 兼容矩阵**：`off` / `trusted` / `standard` / `competitive` / `hardened` 档（§6）与各单项 feature（`check_motion` / `reconcile` / `rate_limit` / `telemetry` / `audit_log` / `correlate` / `provider_3p` / `managed`）的合法组合在此约束，非法组合编译期报错。

## 23. 路线图与基准即规格

路线图（M 对齐 network / world / scene 的里程碑编号惯例，衔接 network M6「反作弊接缝」）：

```text
M1  接缝落地: 对接 network 五钩子点 + 默认 no-op 总装 + feature 门控(引擎侧 prism_net_acheat_api)
M2  快路径守卫: 运动学/加速度/垂直约束 CheckProvider(pac_guard, no_std+alloc, 热路径硬拒绝)
M3  可达性与交互: 查 world 碰撞的穿墙/超距/视锥校验 + 交互冷却距离
M4  资源守恒: 进出账守恒 + 禁负/溢出 + 复制/交易权威事务校验
M5  深路径对账: 事件流重放交叉验证(pac_recon, 复用 network replay) + 抽样策略
M6  限流配额: 令牌桶/漏桶/滑窗 + 分层配额 + 过载自适应降级(pac_rate, 快路径)
M7  计分裁决: 确定性计数聚合 + 可解释硬阈值 + 衰减/滞回(pac_score, 无 ML)
M8  处置分级: flag/throttle/shadow/kick/ban + 误判回滚 + 申诉通道(pac_enforce)
```

## 24. 诚实边界（默认无内核态·可选加固档 / 无 ML / 客户端不可信）

反作弊领域有大量「看起来更强、实则越权或不可持续」的做法，Prism 明确不走，诚实声明如下：

- **默认不做内核态，内核态仅可选加固档（Tier 2，§25.3）**：引擎基座与默认服务**不含**内核驱动 / 反调试 hook / 进程 / 内存扫描 / 提权；内核态只作**可选客户端加固档**，受三条不变量约束——①**安全根不下放**：内核态只抬高作弊成本 + 提供额外软信号，**永不作硬拒绝唯一依据**，被整个绕过 / 伪造也不降低安全下限（安全根永在服务器权威 + 确定性对账）；②**默认不含**：feature(`hardening`) + 平台双门控，默认构建零内核码，主机 / 移动 / Web 自然 N/A，仅桌面 opt-in 才编入；③**责任不转嫁**：驱动签名、整机稳定性（蓝屏 / BYOVD 攻击面）、隐私合规、知情同意、申诉由启用方或第三方 provider 承担，不进引擎 `pkg/`、不进默认服务。**代价诚实**：内核态照样挡不住 DMA / 第二台机 / 读屏自动化，其价值仅限「桌面竞技场景把同机内存读写 / 注入 / 本地脚本的成本抬高一截」，非银弹（design target）。**第一方加固模块 `pac_hardening` 暂列 TODO 待设计**，当前仅经第三方 provider 接入（§16）。
- **不信任客户端检测**：任何来自客户端进程的「我检测到外挂了」都只作噪声过滤 / 计分弱信号，**永不作硬拒绝的唯一依据**。安全根永在服务器权威与确定性对账。
- **无任何 AI/ML**：不含行为模型、异常检测网络、分类器、嵌入、训练式判别。统计全是确定性、可解释硬阈值与计数（§13），跨局关联是确定性聚合（§10）。拒绝 ML 是为了可解释、可复盘、可举证、可申诉——误判代价在反作弊里太高。
- **不靠保密**：威胁模型、规则、阈值公开可审计。强度来自结构（服务器权威 + 对账），不来自「检测逻辑不被逆向」。
- **效果不保证、只标 target**：本机无多端对抗环境，「挡住多少真实作弊」无法实测，一切为 design target，靠上线遥测（§15）持续复盘调参。
- **客户端侧检测本质可破解**：承认客户端是不可信环境，客户端能做的检测终将被绕过——这正是把安全根放在服务器、把反作弊做成「权威回路上的确定性校验」而非「客户端军备竞赛」的根本原因。
- **隐私优先**：只采集游戏内权威状态与提议摘要，不采集客户端系统 / 进程 / 外设信息；managed 形态的数据出域边界见 §21，合规由部署侧承担，设计只定接缝。

## 25. 启动器与引导（服务 supervisor + 客户端 bootstrap，软信号）

反作弊除「校验 / 对账 / 处置」的策略层外，还需要一个把这些拼装起来、拉起来、看住它的**引导组件** `pac_launcher`。按信任边界从松到紧分**三层**（Tier 0 服务端 supervisor·纯增益·安全根所在；Tier 1 客户端 bootstrap·薄·信号全软；Tier 2 可选客户端加固层·opt-in·内核态·信号仍软），边界截然不同：

### 25.1 服务端 supervisor（Tier 0，主角，纯增益）

把分散的 `pac_*` 组件装配成一个可运行、可运维的服务进程，是「独立服务」落地与易维护的关键一环（§1、§17）：

- **装配与引导**：按档位（§6）与部署形态（§3）拉起快路径 `pac_guard` 与深路径 `pac_service` / `pac_recon` / `pac_score` / `pac_correlate`，注入 `AntiCheatProvider` 到 network 接缝（§5、§8）。
- **规则表引导与验签加载**：启动时拉取并**验签**（network crypto §12）最新规则表，失败则回退到本地最后一次成功版本——与 §17 的热更新 / 降级契约同一套机制的「冷启动」入口。
- **健康检查与存活探针**：对快 / 深路径分别暴露 liveness / readiness，供编排系统（sidecar 的进程守护、managed 的托管编排）判活与重启。
- **热重载编排**：协调 §17 的灰度 / A-B / 回滚下发闭环，保证切换事务性、不丢审计流（§16）。
- **优雅降级监督**：监控深路径可达性，深路径断链时确保快路径按 §4 继续用最后规则表运行，恢复后增量追平；**绝不**因深路径不可达而放行或崩溃。
- **三形态一致引导**：embedded（库内 in-process 引导）/ sidecar（独立进程 + 进程守护）/ managed（托管编排拉起），同一套引导契约，迁移只改配置不改游戏代码（§3、§18）。

这一半完全在服务侧、完全契合既有不变量，是「可运维、可计费」的服务形态的自然组成（§21）。

### 25.2 客户端 bootstrap（Tier 1，可选、受限、信号一律软）

传统 AAA「反作弊启动器」常指**客户端**那颗先于游戏拉起的引导程序。Prism **可以**提供一个客户端 bootstrap，但必须严格受限，否则直接违反 §24 的诚实边界：

- **做什么**：会话引导（把握手 / 会话令牌交给 network crypto §12）、可选的**构建版本 / 资源完整性自述**、以及把开源参考守卫规则（§21）的更新投递给客户端。
- **信号一律软**：客户端 bootstrap 上报的一切（版本、完整性自述、环境自述）**只作软信号计分 / 匹配分流**（§13、§14），**永不作硬拒绝的唯一依据**——因为客户端不可信、能自述就能说谎（§7、§24）。
- **边界（Tier 1 自身纯用户态）**：bootstrap 本层是普通用户态引导程序，**自身不做保护进程 / 内核态 / 驱动 / 反调试 hook / 进程 / 内存扫描 / 提权**；被绕过是预期内的，安全根始终在服务器权威与确定性对账（§24）。内核态加固是**另一层、可选**的 Tier 2（§25.3），非 bootstrap 默认职责。
- **可完全不要**：绝大多数项目（尤其 embedded / 可信环境）**无需**客户端 bootstrap；它是 opt-in 的便利件，不是安全必需件。单机 / 可信局域网一律不启用（§6 `off` / `trusted`）。
- **隐私边界**：只上报游戏相关的最小自述，**不采集系统 / 进程 / 外设信息**（§21、§24）。

一句话：**服务端 supervisor（Tier 0）是真正的「启动器组件」，纯增益；客户端 bootstrap（Tier 1）刻意做「薄」——只引导、只给软信号；内核态加固是独立、可选的 Tier 2（§25.3），信号仍软、安全根永不下放到客户端。**

### 25.3 可选客户端加固层（Tier 2，opt-in，内核态，信号仍软，第一方 TODO 待设计）

传统 AAA 反作弊（EAC / BattlEye / Riot Vanguard / 腾讯 ACE）的客户端内核态加固——保护进程、反调试、驱动级内存 / 句柄保护——在 Prism 里是一个**可选的、与 Tier 1 分离的加固层**，物理上由启动器承载（它先于游戏拉起，是唯一能托管保护进程 / 驱动的位置），但受三条不变量严格约束（§24）：

- **安全根不下放**：加固层只做两件事——**抬高同机内存读写 / 注入 / 本地脚本的成本** + **提供额外软信号**（进 §13 计分，不进 §9 硬拒绝）。被整个绕过 / 伪造也不降低安全下限；安全根永在服务器权威 + 确定性对账（§24）。
- **默认不含、双门控**：由 feature(`hardening`) + 平台门控，默认构建零内核码；仅桌面高价值竞技（§6 `hardened`）opt-in 启用；主机 / 移动 / Web 自然 N/A。关掉即编译期移除、无运行时税。
- **责任与合规在启用方 / 第三方**：驱动签名、整机稳定性（蓝屏 / BYOVD 攻击面）、隐私合规、知情同意、申诉由启用方或第三方 provider 承担；不进引擎 `pkg/`、不进默认服务（§1、§21）。
- **当前仅经第三方接入**：Tier 2 是一个**能力槽**，当前由第三方商用内核态 AC 经 `pac_provider_3p`（§16）填充，其内核组件由第三方承担与分发。**第一方加固模块 `pac_hardening` 暂列 TODO 待设计**（独立分发、独立安全评审、独立合规评估后再启动，不阻塞基座与默认服务）。
- **代价诚实**：内核态照样挡不住 DMA / 第二台机 / 读屏自动化（硬件 / 第二机器层面无物可扫）；其价值仅限桌面竞技场景抬高同机作弊成本，非银弹（design target）。那些类别仍靠结构性不下发（network AOI / 遮挡复制）+ 行为统计（§13）+ 对账关联（§10）+ 众包举报复核（§15）兜底。

一句话：**Tier 2 是「可选、可被绕过而不影响安全根」的成本抬升层，当前只接第三方内核态 AC、第一方实现待设计；它让「要内核态的桌面竞技项目」能接上成熟方案，同时让「不要内核态的绝大多数项目」零代价、零内核码、零合规负担。**

## 26. 一句话总结

**Prism Anticheat 是一套独立于引擎发行、插在网络权威回路钩子上的可替换反作弊服务：引擎工作区 `pkg/` 只留零成本接缝 `prism_net_acheat_api`，服务实现独立成仓（`pac_*`，独立版本、可能收费）；架构按「快路径 / 深路径」分离——进程内守卫 `pac_guard` 在提议定序前用常驻规则表 O(1) 硬拒绝物理不可能的作弊（断网也能跑），异步服务侧 `pac_service` 用权威事件流重放对账、跨局关联、可解释硬阈值计分、分级可回滚处置与可举证审计覆盖灰区并支撑运营；规则是数据不是代码，可托管热更新 / 灰度 / 回滚而无需重发游戏服务器；embedded / sidecar / managed 三形态接缝一致、迁移不改游戏代码，收费点落在深路径重活与运营价值；安全根永在 `prism_network` 的「服务器唯一权威 + 确定性对账 + 会话完整性」——默认无内核态（内核态仅可选客户端加固档 Tier 2：opt-in、信号软、安全根不下放，第一方 `pac_hardening` TODO 待设计）、不信任客户端、不靠保密、无任何 AI/ML。**
