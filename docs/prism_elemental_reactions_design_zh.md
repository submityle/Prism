## 0. 定位：这是什么级别的反应引擎

一套**题材无关的通用反应内核**：任意数量的"源"（火把、雷云、玩家技能、诅咒卷轴、辐射源）向世界写入**令牌**，任意数量的"受体"（木箱、水洼、草地、怪物、机甲）持有令牌并按**数据驱动的反应规则**演化，演化中自发涌现出没被显式脚本的连锁（结冰→导电→触电、烧草→产风→助燃、辐射→变异→狂暴）。

三条判据决定它是"一等引擎子系统"而非"特效脚本"：
- **自己的状态模型**：受体不是 bool `isOnFire`，而是一组**语义无关令牌**（tag + 整数强度 + 生命周期）+ 材质 + 媒介层。
- **自己的求解器**：统一整数半环稀疏矩阵内核，一套算子 `Δ=S·v` 同时跑离散反应、化学计量结算；蔓延/扩散是并列的定点 stencil 算子。
- **自己的安全性保证**：编译期可证明"单帧会停 / 合流 / 守恒量不漂 / 无净放大"，运行期可复现、可回放、可 fuzzing。

### 0.1 版本范式脉络（为什么推翻"正交属性"，又为什么统一矩阵观）

v1 用 "正交抽象标量（hot/wet/charged）+ 材质派生" 做状态模型，在三连追问下被判定为错误根基：

| v1 的问题 | 后果 | v2/v3 的修正 |
|---|---|---|
| 正交是假的 | 温度影响导电、湿影响燃——轴之间本就耦合 | 不设计"属性轴"，改设计"令牌 + 令牌间关系" |
| 偏物理写实，装不下奇幻/科技 | 诅咒/祝福/中毒/元素 gauge 既不守恒也不扩散，"3 轴"一上魔法就破产 | **引擎对题材一无所知**：火和诅咒在引擎眼里完全同构，区别 100% 在数据 |
| 属性 schema 太重、难用 | 设计师被迫思考 substrate、守恒、扩散 | 心智模型塌缩到**两个概念**：令牌 + 反应表 |

v2 → v3 的变化（本次重构核心）：v2 已引入化学计量矩阵 S，但仍把"令牌×令牌"当第一视图、把多元反应"溢出到列表"，让 n 元反应像二等公民，也让人误以为"要表达 n 元就要升维成 n 维矩阵"。v3 纠正：

| v2 遗留问题 | 后果 | v3 的修正 |
|---|---|---|
| 以令牌×令牌为第一视图 | 二维只能表二元，abc/abcd 没处放 | **S（关联矩阵）为唯一权威视图**，二元视图是其派生投影 |
| 多元反应"溢出到列表" | 多元像补丁、与二元两套心智 | 多元 = S 的原生列，与二元**同一数据结构、同一算子** |
| 用户直觉"n 元就升维成 n 维矩阵" | 会退回 \|T\|ⁿ 组合爆炸、不可读 | 超图用**关联矩阵（2D）**表示，不用邻接张量（n-D）；元数 = 列非零项数，维度恒为 2 |

## 1. 三条铁律与三段式管线

三条铁律（任何改动不得违反）：
- **源 / 受体解耦**：源只写媒介，受体只读媒介，二者永不直接引用——加源不碰受体，加受体不碰源，抗组合爆炸的第一道闸。
- **逻辑 / 表现分离**：逻辑层整数确定（必须可复现、可联机），表现层浮点随意（粒子/光效/音效，委托 Ember/Volumetric/Audio）。
- **约束账本不约束创意**：引擎只强制"账本平、单帧会停、可复现"等硬不变量，绝不规定"火必须能点燃木头"这种内容。

三段式管线（作者 → 编译 → 运行）：

```
┌─ 作者层 ───────────────────────────────────────────┐
│  令牌表（tag + 5 旋钮生命周期）                      │
│  反应：二元派生视图点格  ╲                           │
│         n 元 S 列编辑器   ╲── 都归一到"反应 = 超边"   │
└───────────────┬────────────────────────────────────┘
                │ 编译器：把每条反应编译成 S 的一列
                │ + 证明安全（合流/停机 φᵀS≤0/守恒 yᵀS=0）
                ▼
┌─ 运行层（整数定点半环）─────────────────────────────┐
│  触发层 RETE → v（每反应本 tick 触发次数）           │
│  结算   Δ = S · v        （稀疏整数 SpMV，顺序无关）  │
│  蔓延   独立定点扩散 stencil（余数守恒，不进 S）      │
│  生命周期推进（decay/lifetime/period/accrue）        │
└───────────────┬────────────────────────────────────┘
                │  事件 / 令牌变更
     ┌──────────┴──────────┬───────────┬───────────┐
     ▼                     ▼           ▼           ▼
  Ember 粒子          Volumetric    Audio       Gameplay
 (火/烟/飞沫表现)     (云雾体积)   (反应音效)   (伤害/状态消费)
```

## 2. 状态模型：语义无关令牌（抗组合爆炸与装下一切的根）

### 2.1 核心立场：引擎对题材一无所知

引擎**不懂**火、水、魔法、辐射。它只认**令牌（Status token）**：一个贴在实体/格点/媒介上的具名计数器。所有语义全在数据。

```
Status {
    tag:    TagId,        // 不透明标识：fire / wet / cursed / irradiated / blessed …引擎不解释
    value:  Fixed,        // 整数定点强度（gauge 量 / 层数 / 剩余时间，取决于生命周期）
    life:   Lifecycle,    // 生命周期：5 个整数旋钮（见 §2.2）
}
```

- **装得下一切**：`fire`(gauge)、`irradiated`(persistent)、`cursed`(persistent)、`blessed`(gauge)、`nanite`(spread) 在引擎眼里**完全同构**，都是"带生命周期的整数计数器"。奇幻/科技/幻想想加什么加什么，引擎零改动。
- **抗组合爆炸**：令牌之间**默认正交、不两两交互**；交互只经过稀疏关联矩阵（§3）。加第 N 个令牌不产生 N² 规则，只产生"该令牌实际参与的那几条反应列"。
- **易用**：设计师心智模型只有两件事——**令牌表** + **反应表**。没有属性 schema、没有物理量纲、没有 substrate。

### 2.2 生命周期 = 5 个整数旋钮（不是不断膨胀的枚举）

"永续 / 自衰减 / 定时 / 循环 / 脉冲 / 蔓延 / 叠加"不是七种独立行为，而是同一组旋钮的取值：

```
Lifecycle {
    decay:    Fixed,     // 每 tick 减多少（>0=自衰减；0=不衰减）
    lifetime: Ticks,     // 存活多少 tick 后到期（有限=定时；∞=永续；=1 配 emit 即脉冲）
    period:   Ticks,     // 每多少 tick 发一次脉冲（>0=循环，如 DOT；0=不循环）
    accrue:   Accrue,    // 强度累积方式：Replace / Max / CappedAdd(cap)（CappedAdd=叠加/层数）
    spread:   SpreadKind,// None / 向邻格定点复制（见 §8 蔓延算子）
}
```

| 你要的行为 | 旋钮设置 | 有界性证明挂靠 |
|---|---|---|
| 永续（诅咒、印记） | `decay=0, lifetime=∞, period=0` | 不自发触发反应 → 不增加帧成本 |
| 自衰减（灼烧、附着 gauge） | `decay>0` | 单调降有下界 0 → 有限步到 0 |
| 定时（限时 buff、炸弹引信） | `lifetime` 有限 | 倒计时良基 → 必到期 |
| 循环（毒 DOT、间歇喷火） | `period>0` | 速率有界（每 period 一次）→ 帧成本有界 |
| 脉冲（爆炸、瞬时触发） | `lifetime=1 + emit` | 瞬时 → 不累积 |
| 叠加（层数 debuff） | `accrue=CappedAdd(cap)` | 有上界 cap → 有界 |
| 蔓延（火蔓延、腐蚀） | `spread≠None` | 预算 + 局部性 → 有界（§8） |

> **诚实澄清（反永动机的边界）**：永续/循环的东西"永远不停"**不是 bug**（火把该一直烧、光环该一直发）。反永动机保证的是"**单帧内不会无限连锁** + **反应不会净放大反应性**"，不是"一切最终归零"。该保证挂在**反应**上（§6.1 的 φᵀS≤0），不挂在生命周期上。

### 2.3 媒介层（Medium）：唯一信道

借鉴 BG3 Surface，把"附着在实体上的令牌（原神式 gauge）"和"铺设在地表/空间的令牌（BG3 式 surface）"**统一成同一层**：源只写媒介，受体只读媒介，二者永不直接耦合。

```
Medium {
    carrier:  CarrierKind,       // Entity 附着 / SurfaceCell 地表格 / VolumeCell 空间体素
    tokens:   SparseSet<Status>, // 该载体上存在的令牌（稀疏，不存不在场的）
}
```

- 附着态与铺设态同构，复用同一套反应/蔓延算子。
- 载体物理由 `prism_physics` / `prism_water` / `prism_volumetric` 提供，本引擎只管令牌演化。

### 2.4 成本分档（L1/L2/L3，按需升级）

令牌模型本身统一，但**存储/求解成本分三档**，绝大多数对象停在 L1/L2：

- **L1 位集态**：令牌退化为"在/不在"的 BitSet，反应=位运算。海量静态物件（草、落叶）。
- **L2 稀疏令牌态**：每载体一个 `SparseSet<Status>`，典型 1~4 个在场令牌。覆盖 95% 玩法。
- **L3 场态**：接入连续场（温度/流体/辐射场），用定点 stencil。关键区域/高配。表示相变（§8）决定升降档。

## 3. 矩阵观：一张权威关联矩阵 + 一个派生投影

你反复追问的"矩阵图到底怎么画、要不要升维"，v3 给出定论：**反应是超边，超图只用一张二维关联矩阵表示，就是 S；令牌×令牌只是它的派生投影。**

### 3.1 反应 = 超边；S = 超图关联矩阵（唯一权威）

把令牌看成超图的**顶点**，一条反应看成一条**超边**——它可以连接 2 个（火+湿）、3 个（火+油+风）、乃至 n 个令牌。超图的标准矩阵化不是"顶点×顶点"的邻接结构，而是**顶点×超边的关联矩阵**：

```
            r1蒸发   r2诅咒点燃   r3三元爆燃(火+油+风)   r4感电
fire        -60      +50          -20                   0
wet         -40        0            0                  -30
steam      +100        0            0                   0
cursed        0       -1            0                   0
oil           0        0          -40                   0
wind          0        0          -10                   0
blast         0        0          +80                   0
electro       0        0            0                  +80
```

- **行 = 令牌，列 = 反应（超边），格子 = 该反应对该令牌的净整数增减**（负=消耗，正=产出）。
- **维度恒为 2，与元数无关**：二元反应（r1）就是列里 2 个非零项；三元（r3）就是 3 个负项 + 产物；n 元就是 n 个非零项。**元数 = 列的非零项个数**，不是矩阵维度。这就是化学几十年只用二维化学计量矩阵就能写 `2H₂+O₂→2H₂O`（三参与者）乃至更长方程的原因。
- **稀疏 CSR 存储**：空格永不物化；一列只存实际参与的几行。加第 N 个令牌 = 加一行，只在它实际参与的列里有非零项。

### 3.2 令牌×令牌 = S 的派生投影（只对二元无损）

v2 把"令牌×令牌关系矩阵"当第一视图是错的。v3 把它降为**从 S 投影出来的二元便捷视图**：

| | 关联矩阵 S（权威） | 令牌×令牌投影（派生） |
|---|---|---|
| 本质 | 超图关联矩阵，令牌×反应 | S 中**恰好二元**的列投到令牌对网格 |
| 能表达的元数 | 任意 n 元 | **仅二元**（三元及以上无损表达不出来） |
| 对 n 元反应 | 原生一列 | 只能"高亮该反应涉及的令牌对"做提示，是**有损投影** |
| 用途 | 存储、运行、证明、n 元编辑 | 编辑期扫覆盖率/对称性/互斥的**只读或便捷视图** |
| 存储 | 唯一真源（single source of truth） | 不单独存，按需从 S 投影生成 |

二元投影里，格子仍可带**类型**，方便人读：

| 格子类型 | 语义 | 例子 | 对应 S 的列形态 |
|---|---|---|---|
| **空** | 两者独立共存，无交互 | 诅咒 × 湿 | 不存在这一列（稀疏零成本） |
| **反应** | A+B → 产物 | 火+湿 → 蒸汽、火清零 | 一列：A、B 负，产物正 |
| **互斥** | A+B → 按优先级一个赢 | 燃烧 × 冰冻 | 一列：消耗双方，产出赢家 |
| **修饰（催化）** | A 在场改变 B 的 `decay`/强度，自身不被消耗 | 风 × 火 → 火衰减变慢 | 读弧：R、P 中等量出现，净为 0 |

> 作者有**两个入口、一个真源**：在二元投影里点格子（快，适合最常见的二元反应）；或在 S 列编辑器里直接写 n 元反应（三参与者以上必须走这里）。两个入口都编译/落库到同一张 S，不存在"两套数据"。

### 3.3 为什么不是 n 维矩阵（邻接张量）——固化结论

你问过"多维矩阵图好不好"。结论：**不好，是倒退。** 这里把理由固化进文档，防止回潮：

| 维度 | 令牌×令牌（2D 邻接） | n 维邻接张量（abc→3D, abcd→4D） | 关联矩阵 S（令牌×反应 2D） |
|---|---|---|---|
| 存储 | \|T\|² | **\|T\|ⁿ 爆炸**（50 令牌·4 元 = 6.25M 格，几乎全空） | 稀疏，只存非零项，与元数无关 |
| 可读性 | 可读 | **>2D 不可读**（立方体 / 超立方体） | 可读（行=令牌、列=反应） |
| 一个结构装几种元数 | 只二元 | 每种元数要一个张量（ragged 张量族） | **任意元数，全在一张表** |
| 角色（催化/修饰） | 格子类型凑合 | 索引对称/有序歧义 | 列内符号自然区分 R/P/读弧 |
| 系数（2H₂+O₂） | 装不下 | 布尔张量装不下 | 列里就是整数系数 |

数学界早有定论：**超边用关联矩阵存储/编辑，邻接张量仅用于谱分析**，正是为了躲 \|T\|ⁿ。所以多元不升维，恒用 2D 的 S。

## 4. 化学计量内核：Δ = S · v

### 4.1 运行时一步整数稀疏矩阵乘

```
Δ = S · v        // v = 本 tick 每个反应触发了几次（整数向量，由触发层给出）
state' = state + Δ
```

- 这**正是** GraphBLAS 式整数半环稀疏矩阵乘；整数加法结合律 → 归约顺序无关 → GPU 跨硬件 bit-identical（§7），确定性白送。
- `r2`：火+诅咒 → 更旺的火（诅咒被吃掉助燃，**凭空净产出火，不守恒**）——魔法反应天然可表达，守恒与否由数据（§4.2）决定，不由引擎强加。

### 4.2 借化学的矩阵，砍掉化学的三条教条

| 化学强加的 | v3 怎么处理 | 为什么 |
|---|---|---|
| 列必须原子守恒 | **不强加**。守恒 = S 的**左零空间**：满足 `yᵀS=0` 的 y 就是被守恒的量 | 魔法/诅咒本不守恒；想守恒的（质量、水量）自动被 y 抓出，不想守恒的让它不在零空间里 |
| 速率 = 质量作用 `v=k∏[反应物]` | **不用连续动力学**。v 由离散**触发谓词**决定（阈值、互斥裁决、催化剂在场） | 游戏要"够了就炸"的离散手感，不是化工连续反应 |
| 只有净矩阵 S | **拆成 R(反应物) 和 P(产物)，S = P − R** | 催化剂 = 在 R、P 等量出现、净为 0（读弧）；R 还是 RETE 匹配的左手边 |

> **关键诚实点**：S 只管"账"，不管"触发"。它只负责"一旦决定各反应触发几次，就并行、精确、顺序无关地记账"。决定 v（谁反应、够不够阈值、互斥谁赢）是另一层非线性逻辑（触发层）。正因 apply 这步是纯线性整数代数，它才能确定性并行上 GPU。

### 4.3 触发层：从状态到 v

- **匹配**：RETE/判别网用 R（反应物模式）增量匹配当前在场令牌，命中即候选反应。O(命中数)，不枚举组合。n 元反应的 R 就是"列里所有负项令牌齐备且过阈值"。
- **裁决**：阈值（强度 ≥ 门槛才触发）、互斥优先级、冷却（原神式内置 ICD）、预算上限。
- **输出**：整数向量 v（每反应本 tick 触发次数），交给 §4.1 结算。

## 5. 多元反应（n 元 / 超多元）= S 的原生列

### 5.1 一列多非零项 = 任意元数（一等公民）

`abc`、`abcd`、超多元在 S 里只是"该列非零行多"。机制零变化，成本 = O(实际反应数)，**与元数无关**。Petri 网关联矩阵 **≡** 关联矩阵 S——不用两套形式，不再"溢出到旁边列表"：多元与二元是**同一数据结构、同一算子、同一证明**。

### 5.2 配套机制

- **通配/类别输入槽**：列的某个负项可声明为"任意带 `flammable` 标签的令牌"，避免为每种可燃物各写一列（抗爆炸）。
- **互斥裁决**：同一 tick 多条列争抢同一批令牌时，触发层按优先级/字典序裁决 v，保证确定。
- **拆链与超多元**：能拆成二元链的（a+b→m, m+c→产物）由编译器选择性拆分以复用中间产物；真正不可拆的超多元保持单列。
- **表示相变兜底**：当"参与者极多的集体反应"（整片森林燃烧）元数爆炸时，切到连续场表示（§8），不再逐个体结算。

### 5.3 编辑体验

- 二元反应：二元投影点格，最快。
- 三元及以上：S 列编辑器——选若干令牌为反应物（负项，可设系数/阈值）、若干为产物（正项）、可选催化（读弧），命名并给反馈事件。
- 编辑器在二元投影上**高亮**该 n 元反应涉及的令牌，提示"这几个令牌被一条多元反应连着"，但真身始终是 S 的那一列。

## 6. 涌现安全栈（只到引擎层：数学驯服，不靠枚举）

涌现是目标不是 bug，但"不可控的涌现"是灾难。引擎用**数学结构**而非"穷举所有连锁"来保证安全——这是能否上 AAA 的分水岭。

### 6.1 反永动机 = 对 S 的一个线性检查

存在非负势向量 φ≥0，使**每一列** `φᵀS[:,j] ≤ 0`，则每次反应都让"总势"单调不增且有下界 → **单帧内反应序列必然有限**。这就是 v1 "自由能 ΔG<0" 落到矩阵列上的精确形态——编译期一次**线性可行性检查（找 φ≥0 使 φᵀS≤0 逐列成立）**即可验，找不到 φ 就报"这套规则可能造永动机"并给出环。

- 吸热/逆向反应（结冰、合成、净产出令牌）**必须显式接外部驱动**（玩家、火把、能量源入账），引擎严格区分**自发**（φᵀS≤0 自洽）vs **被驱动**（外部补势）。
- `period` 循环令牌（DOT）是"被外部时钟驱动"的持续产出，速率有界，不违反单帧停机。

### 6.2 硬不变量 vs 平衡：必须隔离

- **硬不变量**（单帧停机、守恒、确定、合流、无净放大）= 机器保证，设计师不可碰，编译期/CI 强制。
- **平衡**（反应强度、冷却、速率、`decay`）= 设计师旋钮 + playtest 手调。
- 混在一起是绝大多数反应系统失控的根因：设计师为平衡改规则，一不小心破了停机性。隔离开，创意空间最大、事故空间为零。

### 6.3 质量守恒一箭双雕

整数定点扩散 + 确定性余数分配 ⇒ 质量 bit 级精确守恒 + 完全确定（见 §7.2、§8），一个机制同时解决守恒不变量和跨硬件确定性。

### 6.4 全空间涌现安全（不只单点规则集）

单条规则集可证安全，不代表全场景安全——涌现是**空间 × 时间 × 多载体**的联合效应。引擎提供：

- **空间级 fuzzing**：随机布点 + 随机源注入，自动跑数千 tick，断言全局守恒量不漂、无帧成本发散、无 desync。
- **连锁深度探针**：每 tick 记录"反应链最大深度 / 本帧总触发次数"，超阈值告警——把"远处悄悄雪崩"变成可观测指标。

## 7. 确定性与联机（GPU 非确定性如何根治）

"GPU 非确定性"根源不是 GPU，是三样：**浮点非结合律 + 并行归约顺序不定 + 跨硬件实现差异（FMA / 超越函数 / warp）**。先分清两个需求等级：

| 等级 | 要求 | 难度 | 方案 |
|---|---|---|---|
| 同机回放/录像 | 同机重跑一致 | 中 | 固定归约树 + 禁 fast-math（浮点可接受） |
| **跨平台 lockstep 联机** | N 卡/A 卡/Apple **bit-identical** | 高（真难点） | **整数/定点半环，唯一可行** |

### 7.1 根治：整数/定点半环

整数加乘满足结合律且精确 ⇒ 并行归约顺序无关 ⇒ 换任何硬件 bit-identical。`Δ=S·v` 全在整数半环上。躲两个雷：**不用除法**（改乘逆/移位）、**绝不用 GPU 超越函数**（改整数查表/定点多项式）；用**饱和运算**防溢出回绕。`(min,+)/(max,+)/布尔` 半环在整数上天然精确结合。

### 7.2 定点扩散 = 确定性 + 质量守恒

连续场扩散/蔓延看似必须浮点，其实不然：场值存整数，扩散核整数权重 + 移位，整数除产生的**余数按固定规则精确补回**（给索引最小邻格）。结果：质量 bit 级精确守恒 + 完全确定。顺手把 §6.3 的守恒不变量落地。

### 7.3 架构解法 + 兜底

- **把"需要确定"的部分缩到最小**：逻辑层（谁着火、反应结果 S·v、φ 账本、蔓延）整数定点、必须确定；表现层（粒子、光效、烟雾飘散）GPU 浮点随意、不要求确定（委托 Ember/Volumetric）。很多 AAA 干脆不把 gameplay sim 放 GPU，就是这原因。
- **兜底**：每 tick 整数状态校验和（接 `prism_network_design` 的 desync 检测）+ 服务器权威 + 回滚（GGPO 式，反而更依赖确定性 → 又回到整数半环）。

决策表：

| 场景 | 方案 |
|---|---|
| 跨平台联机 lockstep | 整数/定点半环（唯一可行），禁浮点/FMA/超越 |
| 本机回放/录像 | 固定归约树 + 禁 fast-math（浮点可接受） |
| 纯表现（粒子/光） | GPU 浮点随意，不要求确定 |
| 安全网 | 整数校验和 + desync 检测 + 服务器权威/回滚 |

## 8. 表示相变与蔓延算子（最微妙处）

### 8.1 蔓延不进 S，是独立算子

反应 `Δ=S·v` 是"同一载体上令牌间的变换"；**蔓延是载体之间的传播**，是空间扩散 stencil（整数定点、余数守恒），和 S·v 并列，别硬塞进反应列。空间层统一为稀疏邻接矩阵，蔓延 = 半环矩阵乘（换半环切"元胞蔓延/连续扩散/热带最短到达"）。

### 8.2 离散 ⇄ 连续的表示相变

元数轴与空间尺度上存在"离散反应 ⇄ 连续场"的相变，运行期自动升降档：
- **离散令牌节点**（少量参与者，关键个体）：精确、可因果追踪、可逐个结算。
- **连续场 / 连通分量 / 渗流**（海量参与者，集体现象）：O(场)，不逐个结算。
- **交接难点**：
  - 升尺度（个体→场）：N 个着火个体合并为一个火场，需守恒（能量/质量不能凭空增减）。
  - 降尺度（场→个体）：火场边缘生成可交互个体火（玩家能单独浇灭），从场的局部量**确定性采样**出离散个体，避免随机漂移。
  - 判据：密度/连通阈值触发相变；相变点必须**滞回（hysteresis）**，防在阈值附近反复横跳抖动。

## 9. 性能预算与降级矩阵（design target，非实测）

### 9.1 帧预算（目标）

| 阶段 | 预算（中档，目标） | 说明 |
|---|---|---|
| 触发匹配（RETE） | ≤ 0.4 ms | 只扫脏载体 × 匹配反应，O(命中数) |
| 结算 Δ=S·v | ≤ 0.6 ms | 稀疏 CSR 整数 SpMV，可并行分块 |
| 蔓延 stencil | ≤ 0.6 ms | 仅活跃前沿格，余数守恒 |
| 生命周期推进 | ≤ 0.3 ms | 衰减/到期/循环，SoA 批处理 |
| 相变 + 账本校验 | ≤ 0.1 ms | 连通分量增量维护 + 校验和 |
| **逻辑 tick 合计** | **≤ 2 ms** | 其余帧预算留给渲染/物理/AI |

### 9.2 关键性能手段

- **稀疏到底**：令牌 `SparseSet`、关联矩阵 CSR、空间邻接稀疏——不物化任何"全集网格"（更不物化 n 维张量）。
- **脏区增量**：只重算本 tick 有令牌变更的载体及其邻域；静止区零成本。
- **SoA + 分块**：按 tag 分列存储，SpMV 分块映射 CPU SIMD 或 compute dispatch；整数归约顺序无关，分块随意。
- **RETE 索引**：反应物模式预编译成判别网，增量命中，避免每 tick 重扫全规则；n 元反应命中成本仍 O(命中数)。
- **S 编译期静态**：规则集出厂即固定 → S 结构只读、CSR 一次建成；运行时只变 `v` 与 `state`，无增删边（这是 GPU 友好 + 消解动态拓扑风险的根，见 §17.1）。
- **预算降级**：超预算时按"距玩家距离 / 可见性 / 重要度"把远处 L3 场降 L2、L2 降 L1，或拉长 tick 间隔。

### 9.3 降级矩阵

| 配置档 | 令牌态 | 蔓延 | 场模拟 | 适用 |
|---|---|---|---|---|
| 低（移动/远景） | L1 位集 | 关闭或粗格 | 无 | 海量静态物件 |
| 中（主流机） | L2 稀疏令牌 | 活跃前沿 | 关键区域 L3 | 95% 玩法 |
| 高（次世代/近景） | L2+L3 | 全精度 stencil | 多场耦合 | 演出/高配 |

## 10. 易用性（心智模型只有两个概念）

| | v1（属性/channel/律） | v3（令牌 + 反应/关联矩阵） |
|---|---|---|
| 设计师要懂的概念 | 轴、正交、守恒、扩散、律 | **2 个：令牌、反应表** |
| 加一个元素 | 设计 substrate schema | 加 1 个 tag + 点生命周期旋钮 |
| 加一个二元反应 | 想它在物理模型里怎么自洽 | 二元投影点一格 |
| 加一个 n 元反应 | 几乎无法表达 | S 列编辑器选反应物/产物/催化，一列搞定 |
| 空的"属性组合" | 空矩阵格纠结物化 | **不存在**——没写就是没有 |

- **双入口单真源**：二元投影点格（快）/ S 列编辑器写 n 元（全），都落到同一张 S，心智不分裂。
- **5 旋钮生命周期**：永续/自衰减/定时/循环/脉冲/叠加/蔓延全是旋钮取值，不用背行为名。
- **DSL / VS 节点图**：作者层产出，接 `prism_visual_scripting` / `prism_script`；热重载 + 因果探针。
- **可读性/预告**：对外暴露"可反应对象高亮 / 结果预览"数据（供 Gameplay/UI 消费），避免"涌现变 bug 观感"。
- **验收**：新增"类木头但更易燃"材质，作者层 ≤ 10 行，无需改引擎代码。

## 11. 高级功能（Advanced Capabilities：次世代差异化）

前十节是"能跑且安全"的内核；本节把它推到"顶级 AAA 差异化"的高级能力。每条都落在整数/矩阵/半环的既有骨架上（**不引入新范式、不加第二套求解器**），标注借鉴来源与主攻轴，并诚实标注代价。整节是**可选叠加层**，内核（§1–§10）不依赖它们即可成立。

### 11.1 确定性随机（Deterministic Stochastic Reactions）

痛点：要"暴击 / 随机产物 / 概率点燃"的手感，但 lockstep 禁真随机。
做法：用**纯函数哈希 PRNG**，种子 = `hash(worldSeed, tick, carrierId, reactionId, salt)`，产出整数 → 落到概率区间或产物集。无状态、无顺序依赖 → 跨硬件 bit-identical，回滚天然可重算。
借鉴：Factorio / GGPO 确定性 + splitmix/PCG 哈希。主攻：效果 + 确定性。
代价：哈希规格必须随规则集**冻结**（改哈希 = 改存档）。

### 11.2 强度分段产物（Intensity-Banded Outcomes）

痛点：同一对反应物，强弱该给不同结果（小火+水→蒸汽；大火+水→火不灭）。
做法：一条"逻辑反应"编译成**同反应物、不同 guard 的多列 S**，触发层按 gauge 落在哪个整数区间选列。分段用编译期 LUT，无浮点。
借鉴：原神反应随附着量缩放、BOTW 规模相关结果。主攻：效果 + 易用。
代价：列数随分段数线性增（仍稀疏）。

### 11.3 参数化反应模板（Parametric Reaction Templates）

痛点：N 种可燃物 × M 种火源逐对写 = N×M 列，作者爆炸。
做法：写**一条带标签类通配的模板**（"淬灭：任意 `hot` + 任意 `liquid` → 消 hot、产 steam"），编译器按标签类**实例化**成实际列，但作者只维护一条。加一种新液体 = 打一个 `liquid` 标签，自动并入所有相关模板。
借鉴：Noita 材质标签、Factorio 配方族。主攻：组合爆炸 + 易用。
代价：实例化需去重 + 冲突检测（编译期）。

### 11.4 多半环分层（Layered Semirings, One Kernel）

痛点：一次 tick 要同时算"物质账（+,×）""火前沿到达时间（max,+）""可达性预告（布尔）"。
做法：同一张稀疏结构、同一 SpMV 内核，**换半环跑多遍**：`(+,×)` 结算 Δ、`(max,+)` 算最早到达 / 传播波前、`(∧,∨)` 算 telegraph 可达集。代码一套，语义靠半环切换。
借鉴：GraphBLAS。主攻：性能 + 效果。
代价：多遍遍历，但结构复用、缓存友好。

### 11.5 平流与梯度流算子（Advection & Gradient Transport）

痛点：只有各向同性扩散，风吹不动火、热不往冷处流。
做法：在蔓延层（§8，不进 S）并列两个整数守恒算子——**平流**（令牌随 physics/water 速度场定向搬运）、**梯度流**（沿强度梯度下坡流动，如热传导）。都用定点 + 余数守恒，保持 bit-identical。
借鉴：BG3 气体顺风蔓延、流体仿真平流。主攻：效果 + 涌现。
代价：需 physics 提供速度 / 梯度场。

### 11.6 统计远场反应（Statistical Far-Field / Reaction LOD）

痛点：屏幕外整片森林逐格烧，算力浪费。
做法：远场把连通分量当**聚合速率**推进（整片火场一个"每 tick 吞噬 k 格"的宏算子），玩家回到附近时**确定性重建**个体态（余数分配，无漂移）。是 §8 表示相变在"重要度"轴的正式化。
借鉴：Dwarf Fortress / Factorio 屏外抽象。主攻：性能。
代价：远场精度降级，交接点需守恒断言（§13）。

### 11.7 可逆增量与回滚（Reversible Deltas for Rollback）

痛点：GGPO 回滚要存全量状态，反应层状态可能很大。
做法：每 tick 记 `(S, v)` 即可**精确反推** `state = state′ − S·v`（整数无损），反应层回滚只需日志 v，不存全量快照。
借鉴：GGPO / rollback netcode。主攻：性能 + 确定性。
代价：仅反应层可逆；蔓延 / 相变需另存稀疏增量。

### 11.8 UGC / Mod 编译期安全沙箱（Compiler-Gated Modding）

痛点：开放 mod/UGC 反应规则 → 玩家造永动机、刷资源、搞 desync。
做法：mod 规则集加载时**走与一方内容完全相同的编译门**：φᵀS≤0（禁永动机）、`yᵀS=0`（守恒量不被凭空破）、整数路径（禁 desync）、预算上限。**不过门不加载**，附反例链。于是 UGC "构造即安全"，不靠人工审。
借鉴：Factorio / Noita mod 生态 + 本引擎既有编译门。主攻：涌现安全 + live-service 差异化。
代价：门太严可能误杀创意 mod（用 §17.5 的放宽策略兜）。

### 11.9 时间旅行调试器（Time-Travel Debugger / Causal Scrubber）

痛点：涌现 bug "它到底为什么着火"难查。
做法：快照环 + 因果回放日志（§17.6 的 R6 数据）组合成可**倒放 / 逐帧 scrub** 的调试器：选中一个令牌 → 回溯它的完整触发链 → 对比改规则前后的因果差异（regression）。接 `prism_diagnostic`。
借鉴：rr / 时间旅行调试、确定性回放。主攻：易用 + 可观测。
代价：快照环占内存，仅 dev 构建开。

### 11.10 高级功能 × 主攻轴 × 代价 速查

| 功能 | 主攻轴 | 借鉴 | 成本档 | 风险 |
|---|---|---|---|---|
| 11.1 确定性随机 | 效果 / 确定 | Factorio·哈希 PRNG | L1 便宜 | 低（骨架内闭合） |

## 13. 可测性（CPU 可验证的纯函数断言）

- **半环代数律**：随机规则集，断言不同并行划分 `Δ=S·v` bit-identical。
- **守恒（左零空间）**：随机 S，求 `yᵀS=0` 的 y，断言 y·state 在任意反应链前后精确守恒。
- **单帧停机（φᵀS≤0）**：随机规则集，求 φ≥0；fuzzer 专门找"无 φ 可行 / 会造永动机"的规则集并输出环反例。
- **合流性**：对声明确定的规则集，断言不同归约顺序到同一稳态。
- **多元 ≡ 二元链**：对可拆反应，断言"单 n 元列"与"拆成二元链"结果一致（保证 §5.2 的拆链不改语义）。
- **定点扩散守恒 + 确定**：随机场 + 扩散核，断言总量守恒且跨线程划分 bit-identical。

## 14. 落地路线（从可证明价值的最小核做起）

1. **内核验证 demo**（纯逻辑，不依赖渲染，唯一能当场证明价值的点）：整数势账本 + 随机反应规则集 + fuzzer 自动揪出"无 φ 可行 / 会造永动机"的规则集并输出环反例。顺带演示整数扩散精确守恒 + 跨线程划分 bit-identical。
2. **整数半环稀疏 SpMV（Δ=S·v）内核**：同一算子换半环切连续场扩散/离散蔓延/热带最短到达。
3. **关联矩阵 S（R/P 拆分）+ 触发层（RETE）**：催化剂读弧、通配输入槽、互斥裁决、冷却；n 元列从第一天就是原生。
4. **多元反应 + 机制分解**：n 元列、拆二元链、超多元走表示相变。
5. **表示相变**：连通分量/渗流做集体现象，滞回防抖，个体⇄场交接守恒。
6. **作者层：二元投影 UI + S 列编辑器 + 编译器**：合流/停机/守恒校验 + 反例；热重载 + 因果探针。
7. **媒介层 + 源受体解耦**接入 ECS；5 旋钮生命周期、预算/脏区调度。
8. **联机确定性加固**：整数校验和、desync 检测、服务器权威/回滚，接 Network/Anticheat。
9. **可读性/预告接口**：对外暴露高亮/结果预览数据（供 Gameplay/UI）。

## 15. 效果验收口径（design target）

- **涌现**：存在 ≥ 1 条设计师未显式脚本、玩家可复现的三级连锁（如 结冰→导电→触电）。
- **抗爆炸**：新增 1 个令牌，新增反应列 = O(该令牌实际参与的反应数)，不触发已有列重写、不生成空格、不升矩阵维度。
- **多元一等**：三元/四元反应与二元走同一数据结构与算子，新增一条 4 元反应 = S 加一列，无特殊路径。
- **题材无关**：同一引擎零改动承载 奇幻火、科幻辐射、诅咒、祝福——仅靠加令牌 + 加反应列。
- **确定性**：同一输入序列，在不同线程划分/不同机器（整数路径）下 tick 级 bit-identical；联机 1000 tick 无 desync。
- **单帧停机**：无外部驱动时，任意初态单帧内反应序列有限到达不动点；CI fuzzer 零永动机反例。
- **守恒**：左零空间给出的守恒量在任意反应链前后精确守恒（整数精确，无漂移）。
- **性能**：中档预算内逻辑 tick ≤ 2 ms（目标）；万级活跃反应格点不掉帧（目标）。
- **易用**：新增一个"类木头但更易燃"令牌/材质，作者层 ≤ 10 行，无需改引擎代码。

## 17. 风险消解方案（逐条给机制）

### 17.1 R1 — 动态稀疏拓扑在 GPU 上（高 → 低）

**关键认识：S 是编译期静态的。** 规则集出厂即固定，运行时 S 的**结构永不变**，变的只有 `v`（本 tick 触发次数）和 `state`（令牌强度）。于是：
- **结构/值分离**：S 在编译期建成只读 CSR，运行时只做 `Δ=S·v` 的数值乘，无增删边。CSR 对静态结构是最优布局，GPU 友好。
- **空间拓扑用静态网格/分块**：令牌在固定格点间流动，邻接 stencil 结构不变 → GPU 规整派发；真正"动态增删"的只有实体附着令牌（L2），数量小，留 CPU。
- **状态向量的动态性用槽池**：每活跃区固定容量 `SparseSet` + 空闲列表，tick 内 append-only，帧边界 compaction；双缓冲避免读写冲突。

**剩余（低）**：只剩 L2 实体附着令牌的 CPU 侧池管理，规模小、做法成熟。

### 17.2 R2 — 整数定点表达力受限（中 → 低）

- **除以常数** → 乘逆 + 移位；扩散核权重和取 2 的幂 → 除法变移位。
- **非线性曲线**（抗性、衰减落地、阈值响应）→ 编译期烘焙成**整数索引 LUT** 或分段线性/定点多项式，随规则集分发保证跨机一致。
- **编译器守门**：反应公式用到被禁算子（浮点除、`exp/sin`）编译期直接拒绝并提示"改用 LUT 节点"。

**剩余（低）**：作者不能写任意光滑数学——逻辑层刻意约束，表现层不受限。

### 17.3 R3 — 表示相变交接守恒/抖动（中 → 低）

- **双阈值滞回**：升档阈值 ≠ 降档阈值，中间带不切换。
- **最小驻留计时**：进入某表示后停留 ≥ T tick 才允许切回。
- **交接守恒进 CI**：升尺度 `Σ个体量==场量`、降尺度确定性余数分配，整数 bit 精确。

**剩余（低）**：边界一次视觉 pop，表现层过渡混合掩盖。

### 17.4 R4 — 设计师破坏硬不变量（中 → 低）

- **类型层物理隔离**：不变量字段（守恒权重 y、势 φ、拓扑）引擎私有、作者只读；平衡旋钮在另一可写 schema。
- **保存即校验门**：每次保存跑 合流/单帧停机(φᵀS≤0)/守恒(左零空间) 校验；失败拒绝保存并输出**反例链**。
- **CI 门**：规则集变更任一 property-based 测试失败则不可合入。

**剩余（低）**：接近零，唯一残留是流程风险（绕过门），用 CI 门兜。

### 17.5 R5 — φ 误杀合法规则集（中 → 低）

- **仅对 SCC 环求 φ**：无环部分天然停机，只对强连通分量验，比全局 φ 宽松得多。
- **字典序排名函数**：允许多个 φ 组字典序元组，覆盖"此量降、那量才动"的分层终止。
- **被驱动豁免**：作者声明"被驱动"反应（消耗有限外部驱动令牌/能量预算），豁免全局 φ 但仍必停。
- **硬上限兜底**：仍找不到度量时退化为"每反应每 tick 触发上限"，帧成本有界、必停；作者收警告而非枪毙。

**剩余（低）**：被拒的只剩"既无度量、又拒驱动、又拒上限"的规则集——本就该拒。

### 17.6 R6 — 可读性缺失（高 → 中，且残留归 Gameplay）

引擎职责是**保证可读性所需数据是一等输出**，UI 呈现归 Gameplay：
- **预告 API（Telegraph）**：对每个候选反应，不真正结算即输出"会不会反应 + 预测产物"，供 UI 做可反应物高亮/结果预览。
- **因果回放日志**：每次令牌变更记录（触发反应、输入令牌、tick），可问"它为什么着火"并拿到完整因果链。
- **反应命名 + 反馈事件**：每条反应带作者可读名 + 触发事件，供音效/VFX/UI 让玩家感知。

**剩余（中）**：最终观感取决于 Gameplay/UI 用好这些数据——出引擎范围，但"数据存在性"已从风险变保证。

### 17.7 R7 — 过度物理写实（中 → 低，变为内容选择）

- v3 的语义无关令牌本就不含任何物理：守恒、扩散都是**可选**、由数据声明，不是引擎强加。
- **平衡旋钮与硬不变量隔离**（§6.2）：为"好玩"调强度/冷却，不触碰终止/守恒等硬保证。
- **双预设自证中立**：引擎附带"写实物理"与"卡通风格化"两套预设，证明同一内核既能写实也能飞天。

**剩余（低）**：从"引擎偏见"降为"内容选择"，由 playtest 决定。

### 17.8 R8 — 高级功能扩大确定性面与维护成本（中 → 低）

- **零新范式**：§11 全部落在既有整数 / 矩阵 / 半环骨架，不引入第二套求解器。
- **可选分层**：高级功能是 opt-in，内核（§1–§10）不依赖；不开则零成本、零确定性面扩张。
- **规格冻结**：确定性随机哈希、平流 / 梯度核、分段 LUT 全部随规则集版本冻结，改即视为改存档（走迁移），杜绝"同版本不同机不同结果"。

**剩余（低）**：主要是 dev 构建的调试器 / 快照内存，不影响发布态确定性。

## 附录 A：术语

- **令牌（Status token）**：贴在载体上的具名整数计数器（tag + value + 生命周期），引擎不解释其语义。
- **生命周期（Lifecycle）**：decay/lifetime/period/accrue/spread 五个整数旋钮，覆盖永续/自衰减/定时/循环/脉冲/叠加/蔓延。
- **源 / 受体 / 媒介（Source / Receptor / Medium）**：源写、受体读，媒介是唯一信道。
- **超边（Hyperedge）/ 超图（Hypergraph）**：一条连接任意多个顶点（令牌）的边；反应即超边，令牌集即超图。
- **关联矩阵 S（Incidence / Stoichiometry Matrix）**：令牌(行)×反应(列)的稀疏矩阵，`S=P−R`，运行时 `Δ=S·v`；超图的权威二维表示，元数 = 列非零项数。
- **令牌×令牌投影（派生视图）**：从 S 中二元列投影出的令牌对网格，仅对二元无损，用于编辑期浏览。
- **邻接张量（Adjacency tensor）**：k 元超图的 k 阶张量，维度 \|T\|ᵏ；仅用于谱分析，不用于存储/编辑（会组合爆炸）。
- **半环（Semiring）**：`(集合, ⊕, ⊗, 零, 幺)`，换半环换语义；代数律给确定性。
- **势向量 φ / 单帧停机**：非负权重；每列 `φᵀS≤0` ⇒ 总势单调不增 ⇒ 单帧反应序列有限、禁永动机。
- **左零空间守恒**：满足 `yᵀS=0` 的 y 即被守恒量，守恒"可推导"而非强加。
- **Petri 网**：库所（令牌）+ 变迁（反应）+ 读弧（催化剂）的并发模型；关联矩阵 ≡ S。
- **CHAM（Chemical Abstract Machine）**：对分子内容零承诺的多重集重写，"语义无关"的理论根。
- **合流性 / 不动点 / 半格**：不同归约顺序到同一结果；单调迭代收敛到唯一稳态。
- **表示相变**：参与者规模跨阈值时，离散反应 ⇄ 连续场的表示切换。
- **定点（Fixed）**：整数放大定标表示的实数，精确可复现。
- **lockstep / desync**：锁步联机 / 客户端状态发散。
- **确定性随机（Deterministic stochastic）**：纯函数哈希 PRNG，种子含 tick/载体/反应 id，无状态即可复现，lockstep 下 bit-identical。
- **强度分段产物（Intensity-banded）**：同反应物按 gauge 整数区间选不同 S 列，给"强弱不同结果"。
- **参数化反应模板**：带标签类通配的一条模板，编译期实例化成多列，抗 N×M 爆炸。
- **半环分层（Layered semirings）**：同一稀疏结构换半环多遍跑（(+,×)/(max,+)/布尔），一套内核多种语义。
- **平流 / 梯度流（Advection / Gradient transport）**：蔓延层的两个整数守恒算子——随速度场定向搬运 / 沿梯度下坡流动。
- **可逆增量（Reversible delta）**：由 (S,v) 精确反推 `state = state′ − S·v`，反应层回滚免全量快照。
- **UGC 编译门（Compiler-gated modding）**：mod 规则集过与一方内容相同的 φᵀS≤0 / 守恒 / 整数门，"构造即安全"。

## 附录 B：一句话总结

整套引擎 = **"作者在二元投影点格或在 S 列编辑器写 n 元 → 编译成超图关联矩阵 S 的列并证明安全 → 运行时整数半环稀疏矩阵乘 Δ=S·v"的三段式管线**；状态用**语义无关令牌（tag + 整数强度 + 5 旋钮生命周期）**抗组合爆炸并装下魔法/科技/幻想；关系用**唯一权威的超图关联矩阵 S**（令牌×反应，二元/三元/n 元全是列、元数=列非零项数、维度恒为 2），令牌×令牌只是它对二元无损的**派生投影**，坚决不升维成会爆炸的 n 维邻接张量；借化学计量矩阵但砍掉三条教条（守恒从左零空间推导、速率用离散触发谓词、净矩阵拆 R/P 装催化剂）；涌现用"**φᵀS≤0 保单帧停机 + 半格不动点保收敛 + 空间级 fuzzing 保全空间安全**"驯服；确定性用"整数定点半环"根治 GPU 非确定（bit-identical），并顺手用定点扩散解决质量守恒；全程贯穿三条铁律——**源受体解耦、逻辑表现分离、约束账本不约束创意**。在此之上叠一层**可选高级能力**（§11：确定性随机、强度分段产物、参数化模板、多半环分层、平流 / 梯度流、统计远场 LOD、可逆增量回滚、UGC 编译期安全沙箱、时间旅行调试），全部复用整数 / 半环骨架、内核不依赖它们即成立——这是从"能用的内核"到"顶级 AAA 差异化"的那一层。
